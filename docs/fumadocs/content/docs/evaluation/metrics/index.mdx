WorldFoundry ships an in-tree metric layer — a registry of scorers and distribution/perceptual compute routines that runners invoke through a stable contract. Benchmarks decide *what* to measure on *which* data; metrics decide *how* to turn predictions into numbers. Each entry declares inputs, optional checkpoint dependencies, and output shape; runners reference metric IDs and the registry resolves aliases, validates availability, and routes to the right `compute_*`. This keeps model code out of scoring while making scoring reproducible across machines. This hub documents what the repository actually implements — it is not a survey of every published score.

The in-tree catalog spans four families: **scorers & quality** (CLIP, VQA, ITM, face, art, S2V judges), **distribution** (FID, IS, KID, FVD, JEDi, CMMD, Clean-FID), **perceptual pairwise** (LPIPS, SSIM, DINO, mask, layout), and **editing & layout** (SemSR, IRS, CAS, manipulation). Metrics that need pretrained backbones declare those dependencies explicitly — missing checkpoints fail loudly, never silently substitute a proxy. A fifth page, [Registry & reference](/docs/evaluation/metrics/reference), covers discovery (`wf metric list`), parameterized ids, checkpoint staging, and package layout. For benchmark-specific evaluator assets and commands, see [Benchmark Hub](/docs/evaluation/benchmark-hub); individual pages call out approximations and cases where official scripts must be used instead of the generic compute API.

## Built-in existing-results metrics

These metrics score an existing `GenerationResult` JSON/JSONL file with `wf evaluate` and load no model checkpoint.

| Metric | Value per result |
| --- | --- |
| `artifact_count` | Number of output artifacts. |
| `required_artifacts_present` | `1` when every `--required-artifact` name is present, otherwise `0`. |
| `has_artifact:<name>` | `1` when the named artifact is present, otherwise `0`. |
| `numeric` | All numeric metrics, scores, and timings recorded on the result. |
| `numeric:<name>` | One named numeric value recorded on the result, such as `numeric:reward`. |

```bash
wf evaluate \
  --mode existing-results \
  --results-path runs/results.jsonl \
  --output-dir runs/eval/builtin \
  --required-artifact video \
  --metric artifact_count \
  --metric required_artifacts_present \
  --metric has_artifact:video \
  --metric numeric:reward \
  --json
```

The scorecard JSON is written under `--output-dir`.
