WorldFoundry 提供树内 metric 层——由 registry 管理的 scorer 与分布 compute 例程，runner 通过稳定契约调用。Benchmark 决定*在什么数据上测什么*；metric 决定*如何把预测变成数字*。每条注册项声明输入、可选 checkpoint 依赖与输出形态；runner 引用 metric ID，registry 解析别名、校验可用性并路由到对应 `compute_*`，使模型代码不接触打分细节、打分却在跨机器时保持可复现。本 hub 只记录仓库实际实现了什么，并非已发表指标的综述。

树内目录分两个家族：**多模态 scorer**（CLIP、VQA、ITM）与**分布**（FID、IS、KID、FVD、JEDi）。registry 还记录了官方 benchmark runner 常报告的 LPIPS、SSIM、PSNR 等成对分数的方向。依赖预训练 backbone 的 metric 显式声明依赖，缺失 checkpoint 时明确失败，绝不静默替换代理。第三页 [Registry 与参考](/zh/docs/evaluation/metrics/reference) 说明发现方式（`wf metric list`）、参数化 id、checkpoint 落盘与包结构。每个 benchmark 的 evaluator asset 与运行命令见 [Benchmark Hub](/zh/docs/evaluation/benchmark-hub)；各页会标注近似与须使用官方脚本而非通用 compute API 的情形。

## 内置 existing-results 指标

这些指标用 `wf evaluate` 对已有的 `GenerationResult` JSON/JSONL 打分，不加载任何模型 checkpoint。

| 指标 | 每条 result 的取值 |
| --- | --- |
| `artifact_count` | 输出 artifact 数量。 |
| `required_artifacts_present` | 所有 `--required-artifact` 都存在时为 `1`，否则为 `0`。 |
| `has_artifact:<name>` | 指定 artifact 存在时为 `1`，否则为 `0`。 |
| `numeric` | result 上记录的全部数值型 metrics、scores 与 timings。 |
| `numeric:<name>` | result 上记录的单个命名数值，如 `numeric:reward`。 |

```bash
wf evaluate \
  --mode existing-results \
  --results-path runs/results.jsonl \
  --output-dir runs/eval/builtin \
  --required-artifact video \
  --metric artifact_count \
  --metric required_artifacts_present \
  --metric has_artifact:video \
  --metric numeric:reward \
  --json
```

scorecard JSON 写入 `--output-dir`。
