## MetricRegistry

默认 registry 从 `registry.py` 的 `BUILTIN_METRIC_REGISTRY_ENTRIES` 加载全部内置条目。

### 发现与查询

```bash
wf metric list
wf metric list --json

wf metric show fid
wf metric show clip-score --json

wf metric validate fid clip_score has_artifact:generated_artifact
```

Registry key 大小写不敏感，下划线会归一化为连字符（`clip_score`、`clip-score`、`clipscore` 等价）。参数化 id 使用前缀：

- `has_artifact:<name>` — 示例：`has_artifact:generated_artifact`。指定 artifact 存在时返回 1。
- `numeric:<name>` — 示例：`numeric:reward`。从 result metadata/scores 读取名为 `<name>` 的数值字段。

### Python API

```python
from worldfoundry.evals.tasks.metrics.registry import (
    default_metric_registry,
    list_metric_registry_entries,
    validate_metric_ids,
    create_existing_results_metric,
)

for entry in list_metric_registry_entries():
    print(entry.id, entry.family, entry.aliases)

registry = default_metric_registry()
entry = registry.get("clip-score")
canonical = registry.canonical_metric_id("numeric:reward")

payload = validate_metric_ids(["fid", "unknown_metric"])
assert payload["ok"] is False

metric = create_existing_results_metric(
    metrics=["artifact_count", "has_artifact:video"],
    required_artifacts=["generated_artifact"],
)
```

## 已注册指标

方向：**↑** 越高越好，**↓** 越低越好。

### 图像分布（`family=distribution`）

比较 reference 与 generated 图像集合的 set-level 指标。Torch-fidelity 系列（`fid/`、`kid/`、`inception_score/` 等）共用 `_shared/vendor/torch_fidelity/`。

  ]} />

```python
from worldfoundry.evals.tasks.metrics import (
    compute_distribution_metrics,
    compute_fid,
    compute_inception_score,
    compute_clip_fid,
)

scores = compute_distribution_metrics(
    "/path/to/reference",
    "/path/to/generated",
    metrics=("fid", "kid", "prc"),
)

fid = compute_fid("/path/to/reference", "/path/to/generated")
clip_fid = compute_fid("/path/to/reference", "/path/to/generated", feature_extractor="clip-vit-b-32")
is_scores = compute_inception_score("/path/to/generated")
```

FID、KID、Inception Score 和 `compute_distribution_metrics(...)` 接受图片目录或明确的图片文件列表。列表保留传入顺序，与目录使用相同的 RGB 转换和 `samples_resize_and_crop` 预处理。SwAV FID 也接受文件列表，并沿用自身的预处理及 `max_size` 上限。

内置后端通过 `worldfoundry.evals.tasks.metrics._shared.vendor.torch_fidelity` 加载，与已安装的 `torch_fidelity` 包及 TorchMetrics 的导入顺序相互独立。自定义特征提取器和噪声源需注册到该内置包。

Precision 表示生成样本被参考流形覆盖的比例，recall 表示参考样本被生成流形覆盖的比例。在 `compute_distribution_metrics(...)` 中，后端 `input1_*` 参数对应生成输入，`input2_*` 参数对应参考输入。批量接口也在生成集上计算 Inception Score。

SceneFID manifest 的 key 可以是相对于图片根目录的路径或绝对路径。省略 `generated_bboxes_json` 时，参考 key 会按相对路径复用于生成目录，保留子目录层级；绝对参考路径必须位于参考根目录下。缺少图片时会报错，不会回退到其他同名文件。生成图片的文件名或 bbox 不同时，应提供独立的生成 manifest。

SceneFID 的 bbox 约定：四值表示 `(x1, y1, x2, y2)`，五值表示 `(x, y, width, height, extra)`，第五项不参与几何计算。像素坐标与归一化坐标使用相同格式；四值 `xywh` 输入需在调用前转换。

### 视频分布（`family=distribution`，video tags）

<KvCatalog heading="指标" vars rows={[
    { name: "fvd", hintLabel: "方向", hint: "↓", description: <><code>compute_fvd_from_numpy(...)</code>{"、"}<code>compute_fvd_from_frame_dirs(...)</code></>, reads: [{ label: "别名", value: "frechet-video-distance" }] },
    { name: "jedi", hintLabel: "方向", hint: "↓", description: <><code>compute_jedi_from_features(...)</code>{"、"}<code>JEDiMetric(...)</code></>, reads: [{ label: "别名", value: "jedi-mmd, video-jedi" }] }
  ]} />

```python
import numpy as np
from worldfoundry.evals.tasks.metrics import (
    compute_fvd_from_numpy,
    compute_fvd_from_frame_dirs,
    compute_fid_vid,
    compute_jedi_from_features,
)

# uint8 数组形状：(N, T, H, W, C)
fvd = compute_fvd_from_numpy(real_videos, gen_videos, device="cuda")

fvd = compute_fvd_from_frame_dirs(
    reference_frame_dirs=["/path/to/ref_frames/video_0"],
    generated_frame_dirs=["/path/to/gen_frames/video_0"],
)

fid_vid = compute_fid("/path/to/ref_frames", "/path/to/gen_frames")  # 别名 fid_vid

jedi = compute_jedi_from_features(train_features, test_features)
```

`JEDiMetric.load_features(num_samples=...)` 对缓存数组与新提取的特征使用相同的单侧样本上限；读取缓存不会截短磁盘上的文件。特征提取在本地运行，不创建或销毁分布式进程组，加载两侧特征后释放提取器。

JEDi 视频批次使用 `(B, T, C, H, W)`，像素范围为 `[0, 1]`；提取器先转换为通道在首维的视频片段，再执行归一化。Encoder 和 probe checkpoint 必须与模型匹配；缺少权重或形状不匹配时直接报错，不会保留初始化权重继续计算。

使用预计算特征时，`run_jedi_scorer(...)` 报告实际的 `reference_num_samples`、`generated_num_samples` 和 `feature_dim`。原有 `num_samples` 字段在两侧数量相等时记录共同数量，不相等时为 `null`。

Mock JEDi 后端直接用 UTF-8 seed 字节构造 NumPy 种子。相同 seed 和维度在独立进程中产生相同的特征与分数。

## CLI 接口

- `wf metric list` — 列出或 JSON 导出全部 registry 条目。
- `wf metric show <id>` — 查看单条 entry、别名、参数化前缀。
- `wf metric validate <id>...` — 批量解析 id；未知 id 时 exit 1。
- `wf evaluate --metric ...` — **仅内置 existing-results 指标**（`artifact_count`、`required_artifacts_present`、`has_artifact:<name>`、`numeric`、`numeric:<name>`）。
- `wf plan create --metric ...` — 构造 run plan JSON 时使用相同内置 metric ID。

分布指标目前通过 Python 调用。Benchmark runner 在计算官方 metric stack 时可能复用相同底层实现（EvalCrafter IS/FID、MiraBench FVD 等）。多模态 scorer（CLIPScore、VQAScore、ITMScore）通过 `worldfoundry.evals.tasks.metrics.get_score_model(...)` 暴露，实现位于 `execution/runners/_scorers/`。

## 依赖

安装 distribution-metrics extra 以使用 torch-fidelity 等分布指标依赖：

```bash
pip install -e ".[distribution_metrics]"
```

`distribution_metrics` extra 核心依赖包括 `torch`、`torchvision`、`torchmetrics`、`scikit-learn`、`scipy`、`transformers`、`pillow`，以及 `pyproject.toml` 中声明的可选 metric 包。

重依赖保持 lazy import：导入 `worldfoundry.evals.tasks.metrics` 不应要求所有 checkpoint 已就绪，直到具体 `compute_*` 被调用。

修改指标时，请用有代表性的输入与上游实现比对分数，并记录后端版本和结果。私有指标回归测试未包含在公开仓库中。

## 架构

```
worldfoundry/evals/tasks/metrics/
├── __init__.py          # compute_* 与 scorer 入口的 lazy re-export
├── registry.py          # MetricModuleSpec、MetricRegistry、内置与自动发现的 entry
├── _shared/             # 跨 metric helper（torch-fidelity loader、CLIP/aesthetic/pyiqa helper）
│   └── vendor/torch_fidelity/  # Vendored torch-fidelity（Apache-2.0）
├── fid/ kid/ inception_score/  # 图像分布 metric（METRIC_ID、compute、METRIC_MODULE）
├── fvd/                 # Frechet Video Distance 与 I3D 特征提取
└── jedi/                # Video JEPA distance（wrapper.py + vendored JEDi）
```

### 统一 metric 模块布局

每个已迁移的 metric 文件夹导出统一接口：

- `METRIC_ID`、`ALIASES`、`HIGHER_IS_BETTER`、`FAMILY`、`TAGS` — Registry 元数据
- `METRIC_MODULE` — 供 auto-discovery 的 :class:`MetricModuleSpec`
- `compute(...)` / `compute_<name>(...)` — 按 metric family 的稳定 compute API
- 论文 / 仓库链接 — 见 [指标配方子页面](/zh/docs/evaluation/metrics) 各 metric 小节内联说明

已迁移 metric 的 registry entry 通过 `registry.discover_metric_registry_entries()` 注册，而非在 `registry.py` 中硬编码重复项。

### Import 入口

顶层 `metrics/__init__.py` 从各 per-metric 模块 re-export `compute_*` 函数，保持 `from worldfoundry.evals.tasks.metrics import compute_fid` 等现有 import 可用。

Benchmark catalog metric 与官方结果归一化在 `execution/runners/` 完成；benchmark-specific 配置应写在对应的 [Benchmark Hub](/zh/docs/evaluation/benchmark-hub) 子页面。
