WorldFoundry does not equate an accepted option with an active speedup. Each optimization needs a public control, main-path consumption, and runtime `requested / effective / fallbacks` telemetry. Missing kernels, calibration, process groups, or checkpoint weights cause a build-time rejection or an explicit exact/dense fallback.

## Claim boundary

One legacy same-H100 Wan2.2 TI2V-5B diagnostic at 1280×704, 121 frames, 50 steps, CFG 5 measured WorldFoundry at `130.8145 s` after the resident-BF16 fix and FastVideo at `170.9037 s`. Source: `benchmarks/results/20260830/framework_ab_diagnosis/records/full50-bf16weights-worldfoundry-gpu3.json`. This pre-v4 record is retained as historical diagnostic provenance only; Framework A/B v4 will not ingest it into a release summary.

LightX2V's upstream “over 50×” result binds a different complete profile: Wan2.2 A14B, a four-step distilled checkpoint, CFG disabled, 480×832×81 output, NVFP4 weights, DynamicSparse Sage2 with `sparsity_ratio=0.9`, and one RTX 5090. It is a system-level comparison, not the speedup of one sparse kernel in isolation. The TI2V-5B, 50-step, CFG-on workload above neither reproduces that profile nor establishes framework parity or SOTA.

This shows no deficit for that machine, checkpoint, prompt, and sample. It is not an isolated repeated A/B and not a cross-model SOTA claim. Framework A/B v4 accepts a release comparison only when every repetition uses the same physical GPU and UUID, all samples are globally sequential, AB and BA orders are balanced, and the continuous audit covers the passed idle gate through completed output. The certifying default is NVIDIA `Exclusive_Process` compute mode (`--gpu-isolation-proof compute-exclusive`); bounded polling and all `allow-*` escape hatches are diagnostic-only.

The current container exposes only a single `NSpid` value, so it cannot prove a container-PID to host-NVML-PID chain. Its H100s are also shared and use `Default`, not `Exclusive_Process`, compute mode. The v4 protocol therefore fails closed here. A clean-looking smoke run cannot override that missing identity and full-window exclusion proof.

Live 4×H100 BF16/NCCL contracts pass for Torch and FA2 at both one and thirty Wan layers with zero MSE. At full 1280×704, 121-frame, 50-step resolution, a legacy E2E v4 SP1/SP4 run produced identical latent tensors and the same video SHA-256; its contaminated `155.9313 s` and `67.2043 s` timings (diagnostic `2.32×`) are now superseded and remain diagnostic only. The previously reported quality failure came from comparing SP4 against an SP1 artifact generated before later main-path changes.

E2E schema v5 supersedes those records. It fingerprints the inference source tree, workload, checkpoint inventory, and artifact bytes; continuously audits CUDA processes at 0.1-second intervals from the idle gate through completed output; fails closed on query, parser, PID-identity, coverage, or monitor-thread errors; and rejects missing or stale reference provenance before model load. Runtime-effective gates use forward receipts rather than configuration: QKV projection execution, actual static-KV reuse without bypass, the exact SP degree and collectives, branch-per-rank CFG, real sparse-provider calls, request-window CUDA Graph replay, genuinely multi-tile/multi-chunk VAE execution, and low-precision kernels with every dense execution counter at zero. Non-default SP/CFG/VAE-parallel/quantized candidates require both latent and video references. Full-resolution scaling remains uncertified until new v5 runs pass all isolation, quality, runtime, and repetition gates.

The in-tree dynamic per-token/per-channel W8A8 path is now a real Triton kernel, not packed-storage marketing. A contaminated-H100, per-sample AB/BA operator diagnostic measured `1.128×` for the Wan SP4 fused-QKV shape, `1.117×` for MLP-up, and `1.061×` for MLP-down, with kernel counters greater than zero and no fallback. The measured small `8192×1024×1024` shape is dispatched to retained BF16 instead; telemetry calls this `dense_policy_calls`, not a fallback.

The full-pipeline INT8 smoke is deliberately **not certified**. With expandable CUDA segments one profile completed in `153.639 s`, executed 18,200 W8A8 kernels plus 124 calibrated-BF16 calls with zero true fallback, but failed quality badly: latent cosine `0.9092`, video PSNR `17.40`, SSIM `0.7227`, and LPIPS `0.241`. Without expandable segments the extra retained BF16 copy caused a VAE-stage OOM. A later time-embedding/time-projection BF16 hybrid completed in a contaminated `173.5242 s`, hit 18,000 W8A8 kernels plus 124 calibrated-BF16 calls with zero true fallback, and still failed the latent gate (cosine `0.93417`, MSE `0.17157`, PSNR `26.45 dB`). INT8 therefore remains an opt-in experimental kernel/storage mode, not a speed claim. Qualified module-path exclusions and JSON quantization configuration are exposed for calibration, but a profile must pass its own full quality, isolation, and repeated performance gates before release.

| FA2/3/4, xFormers, Sage | dispatcher complete | exact/equivalent or approximate; CPU contract | reports SDPA fallback |

| compile / CUDA Graph | complete for qualified single-rank paths | exact/equivalent; request-window receipts + CPU contracts | compile needs a successful wrapper call/graph trace; Graph needs replay with zero eager/failure; SP + CUDA Graph is rejected |
| TeaCache, AdaCache | complete for qualified single-rank paths | algorithmic approximation; CPU contracts | per-CFG state and dense/hit counters; SP composition is rejected |
| MagCache | complete for qualified single-rank paths | algorithmic approximation; CPU contract | calibrated ratios required; uncalibrated Wan2.2 and SP composition are rejected |
| `taylorseer` (legacy) | whole-stack residual predictor | algorithmic approximation; CPU contract | compatibility name; it is not LightX2V's per-block algorithm |
| `blocktaylorseer` | pinned LightX2V Wan per-block self/cross/FFN predictor | algorithmic approximation; phase-level, gate-refresh, CFG/request-isolation, and receipt contracts | default dense pattern is `[true,false,false,false]`; GPU video-quality/E2E certification is still required; SP is rejected |

| FP8 / NVFP4 | packed wrappers, kernels, per-layer counters | numerical approximation; CPU fallback contracts | build reports pending; ineligible workloads report dense |
| INT8 / INT4 | INT8 dynamic W8A8 Triton plus packed INT4/groupwise storage | kernel execution proven; default full INT8 fails quality | experimental opt-in; calibrated small INT8 uses BF16; INT4/groupwise dequantize+dense |
| GGUF | real tensor loader and compressed runtime storage complete | synthetic loader/storage contracts | no qualified GGUF low-bit GEMM and no local real Wan GGUF certification |
| native Ulysses SP | fused multi-tensor all-to-all/gather and fused 3D RoPE composition complete | legacy full-resolution SP1/SP4 outputs identical; v5 runtime counters required | cache, approximate-attention, and CUDA-Graph compositions are rejected; isolated scaling is pending |
| CFG parallel / SP×CFG | branch-per-rank and mesh complete | equivalent; CPU/mock contracts | CFG degree 2; world size must match |
| VAE mixed precision / spatial tiles | complete | numerical approximation; last-decode-window CPU contracts | certification requires more than one tile and zero single-tile calls |

| STA | tuned-shape adapter | algorithmic approximation; strict request receipt | default 121×704×1280 post-patch grid `(31,22,40)` is untuned and the benchmark CLI fails before CUDA; only `(36,48,48)` and `(18,48,80)` are accepted |
| FastVideo-style VSA | registered model-specific system; generic Wan not certified | algorithmic approximation; metadata/weight audit required | needs a 3D sparse plan and trained `gate_compress` VSA-QAT weights; missing capability/shape/metadata downgrades to reported exact attention and fails certification, while malformed model/provider contracts fail fast |
| V-MoBA | weight-free FastVideo router and Wan processor complete | algorithmic approximation; CPU fake-provider contracts plus request-window layer/chunk receipts | requires a complete grid-specific temporal/spatial/3D chunk and top-k profile plus the three real `fastvideo_kernel` MoBA symbols; provider/shape/device/dtype mismatch fails closed; GPU quality and full E2E performance remain uncertified |
| pinned LightX2V sparse lanes | twelve canonical CLI kinds: `dynamic_sparse`, `sparge`, `nbhd`, `lightx2v_sla_mask`, `flexblock`, `lightx2v_spas_sage`, `draft_attn`, `radial_attn`, `rainfusion_attn`, `svg_attn`, `svg2_attn`, `lightx2v_svg_mask` | algorithmic approximation; complete request/CFG/step/layer and upstream identity receipts | every provider event must execute one exact kernel symbol from a clean pinned LightX2V commit and match its `provider_family`; Draft/RainFusion provider-owned dense phases are separately labeled `provider_dense`; SVG2 reuses a locked 128 MiB `uint8` FlashInfer workspace/wrapper, replans dynamic masks, and keeps centroids request-local; GPU quality/E2E speed remain uncertified |

SP composes with fused 3D RoPE: the kernel receives the rank's global sequence offset and padded-token boundary, and certification requires `fused_rope_calls > 0`. SP with TeaCache, AdaCache, MagCache, feature cache, TaylorSeer, approximate attention, or CUDA Graph remains a construction-time error until rank-synchronized cache decisions, shard-consistent histories/routing, or graph-safe collective lifecycle support exists.

Only rank 0 writes video. Timed ranks synchronize before every repeat. The formal SP runtime gate requires the requested `sp_degree`, the native Ulysses processor, positive measured-window `all_to_all_calls`, `fused_multi_tensor_all_to_all_calls`, and `sequence_output_all_gather_calls`, plus exactly zero `unfused_multi_tensor_all_to_all_calls`. With fused RoPE it also requires positive request-window `fused_rope_calls` and zero `complex_rope_calls`; configuration alone cannot pass. The report includes the max-rank latency distribution, per-rank latency/peak VRAM, profiler-matched collective time, rank consistency, reference latent cosine/MSE/PSNR/max error, and video PSNR/SSIM/LPIPS. Those metrics feed explicit thresholds and the process exits non-zero when the quality gate fails. Reference latent/video files must be the hashed artifacts declared by one passing sibling `report.json`, with matching source, workload, and checkpoint fingerprints. Legacy or changed references are rejected before CUDA initialization. Requested optimizations must have an effective state or an explicit fallback; `--fail-on-fallback` additionally rejects a run that is honest but did not accelerate.

Run the same isolated, order-balanced protocol against either external framework. Each framework uses its own Python environment, while prompt/seed/shape/steps/CFG, physical GPU/UUID, timing boundary, checkpoint fingerprints, MP4 validation, and bootstrap summary stay shared. Framework A/B schema v4 starts the CUDA process audit immediately after the idle gate and samples at 0.1-second intervals through model load and completed output. `nvidia-smi` failure, timeout, or malformed output is fatal. PID authorization uses `/proc` start time plus a proven `NSpid` identity (or the certifying `Exclusive_Process` temporal binding); a disappeared identity is never reused. Every accepted repetition is globally non-overlapping on one GPU, and AB/BA order counts must balance. Older v3 records cannot enter a v4 summary:

Do not reuse that profile for another frame count or resolution. Derive the
actual Wan patch grid first and choose temporal, spatial, and 3D chunk dimensions
that divide it; incompatible VMoBA geometry fails closed before it can be counted
as acceleration.

The launcher enforces a paired performance gate (default median speedup ≥1.0 and bootstrap 95% CI lower bound ≥0.97) and returns non-zero when it fails. Every video must pass shape/frame checks and a complete FFmpeg decode. Cross-framework PSNR/SSIM/LPIPS is opt-in diagnostic data, not a default quality-preservation gate: independent implementations do not guarantee the same seed-to-latent trajectory. Quality acceleration is certified against each framework's own frozen baseline, then with absolute benchmark metrics and human review.

Framework A/B v4 now has code-level runtime-authenticity gates for both reference attention lanes. FastVideo uses worker `collective_rpc` records to require one consistent accelerated backend and implementation class across T2V self/cross attention, one successful forward hook per role, and a direct call to the concrete FA4 → FA3 → FA2 entry point selected by the upstream default/varlen resolvers; wrappers and hooks must then be restored or removed. An outer `FlashAttentionImpl.forward` call without a concrete kernel call fails. LightX2V binds the requested mode to concrete attention classes and callable kernel symbols, then requires one successful self/cross `apply` call and method restoration. Missing or mixed identities, absent symbols, zero calls, substituted/non-accelerated backends, issues, or fallbacks fail closed.

Those gates and their CPU mocks are complete; formal v4 GPU certification is not. The current shared/default-mode host cannot produce a certifying record, so fresh `Exclusive_Process` runs are still required. The gates prove only the requested reference attention path, not every upstream cache, sparse, quantization, or parallel technique. Existing cross-framework timings therefore remain diagnostics and do not establish complete technique parity or SOTA.

## Audit what ran

```python
dit = pipe.native_pipeline.components.denoiser.runtime_optimization_report()
vae = pipe.native_pipeline.components.decoder.runtime_optimization_report()
print(dit["requested"], dit["effective"], dit["fallbacks"], dit["runtime"])
print(vae)
```

Inspect quantization after a forward. `*-wrapper-installed (runtime-pending)` proves only weight conversion. An actual provider and `low_precision_kernel_calls > 0` prove kernel execution. Calibrated BF16 dispatch is separately counted by `dense_policy_calls`; packed dequantize+dense and true error/eligibility fallbacks remain visible and cannot be counted as acceleration.

Attention proof is also forward-dependent. Eager execution requires target-provider `attempts == successes > 0`; `torch.compile` requires `compiled_graph_traces > 0` plus `runtime.compile.calls > 0` because host call counters do not execute on every compiled replay. Both paths still require provider fallback, error, and quarantine counters to remain zero.

The release gate is stricter than those basic diagnostics:

- Fused QKV requires `runtime.qkv_fusion.fused_blocks > 0`. Eager execution needs `eager_projection_calls > 0`; compiled execution needs `compiled_graph_traces > 0` plus `runtime.compile.wrapper_installed=true`, `calls > 0`, `failures=0`, and `last_error=null`.
- Fused RoPE requires `runtime.fused_rope.installed_blocks > 0`, with `torch_fallback_calls`, `provider_failures`, `quarantined_skips`, and `malformed_receipts` all zero. Eager execution needs `provider_calls == eager_calls > 0` and exactly `provider_paths=["triton_hidden_qk_rmsnorm_rope_3d"]`; entering the public fused operator but falling back to Torch does not pass. Compiled execution instead needs `compiled_graph_traces > 0` together with the executed, failure-free compile-wrapper receipt above.
- Static cross-KV requires `wrapped_blocks > 0`, `effective=kv-reuse`, positive request-window `hits`, `misses`, and `condition_hits`, plus `bypasses=0` and `bypass_kwargs=[]`.
- STA/VSA requires `runtime_effective=true`, `kernel_attempts == sparse_calls > 0`, zero kernel/dense fallback, and an exact-whitelisted matching `fastvideo_kernel` provider symbol. Sparse-plan `scheduled_dense_calls` are allowed only when finalized request/branch/step/layer receipts cover the complete workload. VMoBA additionally requires requested `kind=vmoba`, provider path `fastvideo_kernel.moba_attn_varlen`, the exact workload grid and wrapped-block count, unique events for every branch/step/layer, route/profile agreement, and exact event/counter totals. Its three provider symbols and every shape/device/dtype boundary fail closed.
- The twelve pinned LightX2V sparse kinds require the canonical provider symbol selected by their normalized operator, the exact `provider_family`, checkout commit `6fb7c1362b89d4908a9ea197bac4fbd7482ee2d5`, a clean source tree, the deterministic source fingerprint, and one strict flattened event emitted by every real provider call. DraftAttention's first-layer warmup and RainFusion's provider-scheduled dense phase count as `provider_dense`; they are neither sparse calls nor fallbacks, and both remain in the same complete event ledger. SVG2 additionally requires device/backend wrapper and 128 MiB `uint8` workspace reuse, a new FlashInfer plan for every dynamic mask, and request-local K-means centroids. The obsolete nested `provider_receipt` schema is rejected. Event totals are recomputed instead of trusting reported counters. Compatibility aliases such as `sla` or `sagesla` remain excluded because they are ambiguous. The upstream `sage_attn2_k_int8_v_fp8` registry entry is explicitly fail-closed in Wan A/B because it expects `(k_int8, k_scale)` and `(v_fp8, v_scale)` inputs, while the pinned Wan generator supplies floating K/V and has no audited per-layer quantize/cache/invalidation lifecycle.
- SLA top-k profiles are also rejected before CUDA launch when pinned LightX2V's integer truncation would select zero key blocks. Launching its provider with that empty LUT can produce finite but invalid output on short sequences, so such a sample cannot count as sparse execution evidence.
- FastVideo learned SLA requires the exact `fastvideo_sla` or `fastvideo_sagesla` kind, canonical provider class/family from clean commit `1b2b2a0161bc6b3b80158d1fa6380a051c6530c7`, one audited checkpoint layout, complete self-attention layer coverage, FP32 `proj_l`, matching per-layer/global projection fingerprints, unique global/per-layer call indices, exact timestep/top-k/feature-map values, and complete branch/step/layer events. Missing learned weights, a test-injected/dirty provider, mixed layout, source or projection mutation, dense substitution, or a summary inconsistent with its events fails closed.
- Async block offload requires `runtime.offload.effective=true`, positive request-window async-copy and forward counters, zero synchronous-copy counters, zero pageable CPU sources, and `peak_active_layers <= 2`. Hook installation alone remains runtime-pending and cannot certify overlap.
- CUDA Graph counters are request-window deltas. The current request needs `(capture > 0 or graphs > 0)`, `replay > 0`, and `eager = capture_failed = 0`; an existing graph may therefore certify a later request only when that request actually replays it.
- Spatial VAE decode needs `last_spatial_tile_count > 1`, a tiled call, and `single_spatial_tile_calls=0`. Temporal streaming needs `last_temporal_chunk_count > 1`, a chunked call, and `single_temporal_chunk_calls=0`. Lifetime totals cannot satisfy either gate.
- Quantization needs `low_precision_kernel_calls > 0`, while `packed_weight_calls`, `dense_policy_calls`, and `dense_fallback_calls` are all zero and `fallback_reasons` is empty. A calibrated dense call is honest telemetry, but it is not a fully low-precision certified candidate.

Before publishing, fix checkpoint/prompt/seed/shape/steps/CFG/encoding/GPU; run repeated same-card, globally sequential, balanced AB/BA samples; gate exact paths on latent error and approximate paths against their own baseline plus absolute quality and human review. Never count pending, configuration-only, dense-fallback, single-tile, contaminated, legacy-schema, or escape-hatch samples as proof of acceleration, and do not extrapolate SOTA from one H100 sample.
