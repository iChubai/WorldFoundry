AC3D is Snap Research's **ControlNet-style** camera plugin for CogVideoX: text plus a source video and **19-column** camera pose rows go in; a camera-steered clip comes out. WorldFoundry vendors the official infer runtime under `worldfoundry/synthesis/visual_generation/ac3d/ac3d_runtime`, launches it through the installed `worldfoundry.synthesis.visual_generation.ac3d.runtime` module, and exposes it as `AC3DPipeline`. Aliases `ac3d-cogvideox`, `ac3d-2b`, and `ac3d-5b` resolve here.

The official paper is [AC3D: Analyzing and Improving 3D Camera Control in Video Diffusion Transformers](https://arxiv.org/abs/2411.18673) (CVPR 2025, arXiv 2411.18673). Project: [snap-research.github.io/ac3d](https://snap-research.github.io/ac3d/). Code: [snap-research/ac3d](https://github.com/snap-research/ac3d). License: **Snap non-commercial research**.

The adapter follows the official `inference/cli_demo_camera.py` camera-control path and keeps the official **2B ControlNet shape** settings even when the 5B ControlNet file is also staged.

## What it is for

Re-render a clip along a prescribed 3D path. Prefer the RealEstate10K-style 2B ControlNet demo.

Launch `wf run ac3d`.

Score on [CameraBench](/docs/evaluation/benchmark-hub/camerabench) — directly measures camera-control precision in generated video.

## Runtime contract

Required: `prompt` and `video`; optional: `image`; `actions`: camera_index, camera_index_range, camera_pose_rows; artifacts: `ac3d.mp4`.

Base weights: `THUDM/CogVideoX-2b` and `THUDM/CogVideoX-5b`. ControlNets stage under `$WORLDFOUNDRY_CKPT_DIR/ac3d` as `2B/checkpoint-10000.pt` and `5B/checkpoint-10000.pt`. Other pose formats must be converted to the 19-column convention first.

## Running in WorldFoundry

Dedicated environment `ac3d` (Python 3.10, CUDA 12.4, torch 2.4) — not ABI-compatible with `worldfoundry-unified-cu128`. Stage CogVideoX base plus the matching ControlNet locally. Run `wf run ac3d`. License: Snap non-commercial research.
