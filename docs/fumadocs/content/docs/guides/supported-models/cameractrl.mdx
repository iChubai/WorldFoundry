CameraCtrl pioneered plug-and-play camera control for text-to-video diffusion: it trains a camera encoder over Plücker embeddings so trajectories can steer generation without retraining the base model. WorldFoundry runs it in-tree following the official trajectory text-to-video demo: a text prompt and a camera trajectory file produce a video.

## What it is for

Use `cameractrl` when the viewpoint must follow a given camera path.

Per the publication (arXiv 2404.02101), camera poses are encoded as Plücker embeddings and injected through a trainable camera encoder attached to a frozen video diffusion base (AnimateDiff in the official release). It is published by The Chinese University of Hong Kong / Shanghai AI Laboratory.

Tasks: world, video, camera control, and world model. Output modalities: video.

Suggested benchmarks: [CameraBench](/docs/evaluation/benchmark-hub/camerabench) (The standard camera-trajectory adherence evaluation).

## Runtime contract

Inputs `prompt` and `trajectory-file` (bundled samples are used when omitted); options `frames`, `fps`, `height`, `width`, `steps`, `guidance-scale`, and 3 more; artifacts `cameractrl.mp4`.

CLI task profiles: `trajectory-video`. WorldFoundry binds `CameraCtrlPipeline`.

Family status: **Verified**.

Recorded `trajectory-video` defaults: frames=16, fps=8, height=256, width=384, guidance_scale=14.0, seed=42.

The runner follows the official demo trajectory contract — supply a camera trajectory file and a text prompt.

## Running in WorldFoundry

Generate a camera-controlled clip with `wf run cameractrl --pipeline.task-profile trajectory-video`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 11.3).

Weights: `hehao13/CameraCtrl`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh cameractrl`. Add `--download` to fetch missing public checkpoints.
