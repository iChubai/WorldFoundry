DB-CogACT is the CogACT recipe rebuilt inside Dexmal's Dexbotic framework, with an unusually complete released checkpoint zoo: single-arm and dual-arm foundations plus task checkpoints for LIBERO, CALVIN, and SimplerEnv, all Apache-2.0. WorldFoundry builds the official Dexbotic policy in process and emits LIBERO action traces.

## What it is for

Use `db-cogact-libero` to predict robot actions from observations and a language instruction.

WorldFoundry follows the Dexbotic v1 inference contract: requests carry observation.prompt and observation images, and the policy follows the CogACT VLM-plus-DiT-action design re-implemented in Dexbotic.

Tasks: VLA, VLA action prediction, and VLA policy rollout. Aliases: `dexbotic`, `db_cogact`, and `dexbotic-cogact`.

Suggested benchmarks: [LIBERO](/docs/evaluation/benchmark-hub/libero) (Dedicated libero-db-cogact checkpoint), [CALVIN](/docs/evaluation/benchmark-hub/calvin) (Dedicated calvin-db-cogact checkpoint), [SimplerEnv](/docs/evaluation/benchmark-hub/simpler-env) (Dedicated simpler-db-cogact checkpoint).

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted); options `official-policy-observation`; artifacts `action_trace` and `db-cogact_action_trace.json`.

CLI task profiles: `default`. WorldFoundry binds `DBCogACTPipeline`.

The native runtime reuses checkpoint-backed model and tokenizer resources. Each request receives its own policy wrapper and resolved action normalization: `norm_stats`, `norm_stats_path` / `normalization_stats_path`, checkpoint `norm_stats.json`, then the `[-1, 1]` default. Updating a statistics file at the same path takes effect on the next request without reloading model weights. The DDIM schedule is rebuilt when a request changes `num_steps`; requests with the same step count reuse it.

Validated with `Dexmal/libero-db-cogact`: the LIBERO path writes a finite action trace of shape **`[1, 16, 7]`**. The CALVIN and SimplerEnv checkpoints are wired but have no separately validated trace.

Family status: **Runner parity pending**.

Pick the checkpoint matching your benchmark: libero-db-cogact, calvin-db-cogact, or simpler-db-cogact; SArm/HArm foundations serve fine-tuning.

Validation covers the LIBERO path only: `Dexmal/libero-db-cogact` produces a finite [1, 16, 7] action trace. The CALVIN and SimplerEnv checkpoints are wired but not separately validated.

The released checkpoints use the native Transformers Qwen2 tokenizer. `trust_remote_code` defaults to `false`; requests that enable it are rejected before model/tokenizer cache lookup. Stage the tokenizer assets alongside the checkpoint.

## Running in WorldFoundry

Run the policy with `wf run db-cogact-libero --pipeline.task-profile default`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8, torch>=2.6.0).

Weights: `Dexmal/libero-db-cogact`, `Dexmal/Dexbotic-CogACT-SArm`, and `Dexmal/Dexbotic-CogACT-HArm` among others. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh db-cogact-libero`. Add `--download` to fetch missing public checkpoints.
