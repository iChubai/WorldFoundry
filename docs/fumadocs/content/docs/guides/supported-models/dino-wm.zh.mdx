DINO-WM 在预训练 DINOv2 视觉特征（而非像素）上构建世界模型：预测未来 patch 特征，并通过针对目标特征状态优化动作序列来规划机器人行为——无需重建即可零样本规划。本 catalog 中官方规划/评估路径已内置树内，包括必需的 env 仿真器。

## 用来做什么

需要动作条件世界步进时选 `dino-wm`：记录动作与帧进、滚动生成出。用来做交互世界推理，不是把 prompt 倒进文生视频。

按上游项目，ViT 预测器在动作条件下向前滚动 DINOv2 patch 特征；规划是特征空间中的模型预测控制。推理入口从 data/models/runtime/configs/dino_wm/conf 加载运行时配置，内置的 dino_wm/env 仿真器为官方规划运行有意保留在树内。该模型由纽约大学（NYU）发布。

catalog 记录的任务包括 visual-feature-world-model、predictive-coding、机器人世界模型、wall-planning。

基于 DINO 的世界模型动力学，不是像素视频生成器。

## 运行时契约

必填 `prompt`、`image`、`video`；可选 `actions` (robot_action, planning_action)；产物 `generated_world`、`dino-wm.mp4`。

记录的任务 profile：`visual-feature-world-model`、`predictive-coding`、`robot-world-model`、`wall-planning`。绑定的 pipeline 类是 `DinoWMPipeline`。

系列状态：**Runner 一致性待确认**。

`wall-planning` 记录默认值：seed=0。

执行仍受 checkpoint/任务资产限制，但不再依赖外部仓库检出。 完整运行时一致性在 OSF checkpoint/任务资产布局就位前保持 blocked。

## 在 WorldFoundry 中运行

catalog 启动命令是 `worldfoundry-eval run dino-wm --pipeline.task-profile wall-planning`。上方命令构建器按已记录任务切换 `--pipeline.task-profile`，发出的仍是 `worldfoundry-eval run`。

运行环境是统一 profile `worldfoundry-unified-cu128`（Python 3.11，CUDA 12.8）。

本卡片未记录公开 checkpoint id；按使用说明就位权重。就位权重用 `bash scripts/inference/prepare_model_infer.sh dino-wm`。

状态：**Runner 一致性待确认**。
