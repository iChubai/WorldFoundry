DreamDojo 从初始图像与归一化机器人动作预测机器人视角视频。WorldFoundry 通过原生 Cosmos 组件接入离线 2B GR-1 后训练 teacher 与独立低步数因果学生入口。

## 用来做什么

用 `dreamdojo-2b-gr1-distilled` 以动作推进世界并渲染出相应画面。

动作条件 Cosmos DiT 为每个后续潜帧组合四个 384 维动作，将投影注入时间步与 AdaLN embedding。Reason1 文本条件与 Wan 编解码共享。Teacher 使用 UniPC，因果学生使用干净 KV 预填充与一至四步 TrigFlow 采样。该模型由英伟达（NVIDIA）发布。

任务：世界模型、机器人。同系列还有 `dreamdojo-2b-gr1-action-conditioned`。

推荐评测：[EWMBench](/zh/docs/evaluation/benchmark-hub/ewmbench)（显式动作条件下的机器人视频预测）。

## 运行时契约

输入 `prompt`、`input-path`（不传时使用内置示例）；参数 `height`、`width`、`steps`、`guidance-scale`、`seed`；产物 `dreamdojo_world.mp4`。

CLI task profile：`interactive-video`、`robot-world-generation`。绑定的 pipeline 类是 `DreamDojoPipeline`。`interactive-video` 的默认值：height=480, width=640, steps=35, guidance-scale=7.0, seed=42。

建议从 `dreamdojo-2b-gr1-distilled` 开始。该系列共有 2 个 variant，可在上方命令构建器中切换：`dreamdojo-2b-gr1-action-conditioned`（`robot-world-generation`）：Runner 一致性待确认、`dreamdojo-2b-gr1-distilled`（`robot-world-generation`）：Runner 一致性待确认。系列状态：**Runner 一致性待确认**。

提供一幅初始图像、归一化 384 维空间中的完整 12 步动作块、转换后的 EMA 权重、Cosmos 视频 tokenizer，以及 Reason1 文本权重或显式预计算 embedding。每块生成 13 帧，较长序列复用上一块的最终生成帧。

尚未验证官方数值一致性、GR-1 评测质量与机器人任务成功率。蒸馏推理通过 dreamdojo-student 使用显式学生权重，不能与 teacher 权重互换。暂不支持其他模型规模。

此模型是机器人世界模型，不是输出动作的 VLA 策略。

提供一幅初始图像与已经归一化的动作，形状为 `[N,384]` 或 `[1,N,384]`，其中 `N` 是 12 的正整数倍。每块在 480×640、5 fps 下生成 13 帧。续接使用上一块最终生成帧作为新观测，并移除重复的边界帧。动作文件支持 `.npy`、`.json` 与 PyTorch tensor。

统一动作布局包括 GR-1 `[0,58)`、G1 `[58,101)`、YAM `[101,147)`、AgiBot `[147,169)`、MANO `[220,352)` 与潜动作 `[352,384)`。数据集专用归一化由调用方完成。

## 在 WorldFoundry 中运行

运行 `wf run dreamdojo-2b-gr1-action-conditioned --pipeline.task-profile interactive-video` 推演世界模型。在上方命令构建器中切换任务，即可改变 `--pipeline.task-profile`。

运行环境：独立环境 `dreamdojo`（Python 3.10，CUDA 12.8，torch==2.7.0）。

权重仓库：`nvidia/DreamDojo`、`nvidia/Cosmos-Predict2.5-2B`、`nvidia/Cosmos-Reason1-7B`。准备环境并检查本地资产：`bash scripts/inference/prepare_model_infer.sh dreamdojo-2b-gr1-action-conditioned`；下载缺失的公开权重时加 `--download`。

许可证：NVIDIA Open Model License。

准备 GR-1 EMA 权重、Cosmos-Predict2.5 视频 tokenizer 与 Cosmos-Reason1-7B 文本编码器。需要时，公共加载入口会自动将分布式 checkpoint 分片转换为 `model_ema_bf16.pt`。

如已准备官方 Reason1 特征，可用 `text_embeddings_path` 替代 `text_encoder_path`。特征形状必须为 `[1,S,100352]`；该路径使用实际提供的文本 embedding，不再加载文本编码器。
