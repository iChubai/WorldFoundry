EgoWM predicts the **first-person** video a moving agent would see, given a view plus navigation actions. Variants: `egowm-svd-3dof` and `egowm-svd-25dof` on a **Stable Video Diffusion** backbone (`anuragba/egowm`). WorldFoundry binds the official 25-DoF SVD infer path through a user-staged source checkout as `EgoWMPipeline`. Architecture internals beyond those variants are not stored here. Institution is not recorded.

Paper: [arXiv 2601.15284](https://arxiv.org/abs/2601.15284). Project: [egowm.github.io](https://egowm.github.io/). Code: [miccooper9/egowm](https://github.com/miccooper9/egowm).

Config import should pass. **Real generation emits a runtime plan** until checkpoints and assets are staged. Missing assets are reported by the plan, not catalog blockers. Runner: `implemented`.

## What it is for

Egocentric navigation world model with action-conditioned 3-DoF and state/action-conditioned 25-DoF variants.

The default 25-DoF route needs an image and physical conditions from the same trajectory.

## Runtime contract

Required: `image` and `prompt`; optional: `video`; `actions`: navigation_action, egocentric_action; artifacts: `generated_video` and `egowm.mp4`.

| Knob | Default |
| --- | --- |
| Size | **512×512** |
| Frames | **8** |
| Steps | **25** |
| FPS | **7** |
| Seed | **42** |
| `motion_bucket_id` | **180** |
| Conditions | Paired `conditions_path` JSON (required for 25-DoF) |
| Student | `$WORLDFOUNDRY_CKPT_DIR/anuragba--egowm/svd_25dof_nav.pth` |
| SVD base | `stabilityai/stable-video-diffusion-img2vid` |
| Source | `$WORLDFOUNDRY_MODEL_SOURCE_DIR/egowm` commit `4a24b6fb` |

The default `variant=25dof` requires an explicit initial image and a JSON file with `physical_initial_state` (25 numbers) and `physical_actions` (one 25-number row per generated frame). Actions are physical differences between robot states sampled six source-video frames apart. The runner applies the official navigation state and action normalization. The image must belong to the same trajectory; no image is supplied by default. Use `smoke_synthetic=true` only to check that the model loads and generates; its zero state and synthetic actions do not validate robot motion. For the 3-DoF checkpoint, set `variant=3dof` and use the separate `action_scale` offset without a conditions file.

## Run in WorldFoundry

Status: **One official paired 25-DoF navigation sample verified on GPU**. The public pipeline generated eight future frames plus the input from a matching EVE1x validation image, initial state, and 25D action sequence. That single-sample result does not establish calibrated robot displacement or general navigation accuracy. Stage `anuragba/egowm` and `stabilityai/stable-video-diffusion-img2vid` locally; missing files fail at load. Supply a paired image and conditions JSON to the 25-DoF task. Catalog VRAM is unset.
