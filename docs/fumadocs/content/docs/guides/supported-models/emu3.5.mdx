Emu3.5 is BAAI's native multimodal generation model for interleaved text and images. WorldFoundry has a registered adapter, but the staged checkpoint declares an Emu3 architecture that the installed Transformers runtime cannot resolve. Checkpoint-backed inference is blocked before model loading; no video output is claimed.

## What it is for

The official checkpoint describes text and image generation. The `vla.reasoning` task label is catalog metadata; no robot-action policy or action-trace output has been verified.

The Emu series treats images and text as one token stream for next-token prediction — no separate diffusion decoder in the loop, per BAAI's public releases. This repository records the prompt+image input contract and the model_response artifact; parameter counts and internals of the 3.5 revision are not recorded here. It is published by Beijing Academy of Artificial Intelligence (BAAI).

Catalog tasks include multimodal-generation, image-generation, and vla reasoning. Catalog aliases include `emu3p5`, `emu3_5`, and `BAAI/Emu3.5`.

## Runtime contract

Required `prompt`; optional `image`; artifacts `emu3.5.json`.

Recorded task profiles: `multimodal-generation`, `image-generation`, and `vla.reasoning`. WorldFoundry binds `Emu35Pipeline`.

Integration status: **Blocked**. Runner parity remains pending.

Transformers 4.57.6 cannot resolve the checkpoint's `config.model_type` value `Emu3`. A reviewed, compatible loader is needed before a text/image response can be verified.

The registered adapter currently stops before model loading.

## Running in WorldFoundry

The catalog command is `worldfoundry-eval run emu3.5 --pipeline.task-profile multimodal-generation`. It cannot currently load the staged checkpoint.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Recorded weight repositories include `BAAI/Emu3.5`; the checkpoint is already staged in this workspace.

Status: **Blocked**.
