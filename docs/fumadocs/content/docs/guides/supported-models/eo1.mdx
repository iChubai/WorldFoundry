## What it is for

Pick `eo1` when you want the catalog VLA policy: instruction and observation in, an action trace out. Use it to roll the recorded policy, not to train a new one.

The runtime contract is a Hugging Face Transformers processor with a select_action interface. Architecture internals beyond the official repository pointer (EO-Robotics/EO, pinned head 451c363d) are not recorded in this repository.

Catalog tasks include vla, embodied vla, vla policy rollout, and robot policy. Catalog aliases include `eo-1` and `embodied-one`.

## Runtime contract

Required `image`, `prompt`, and `state`; optional `model_id` (eo1), `policy_family`, and `action_representation`; artifacts `action_trace` and `eo1_action_trace.json`.

Recorded task profiles: `vla`, `embodied_vla`, `vla.policy_rollout`, and `robot_policy`. WorldFoundry binds `EO1Pipeline`.

Family status: **Runner parity pending**.

Checkpoint absence is reported by runtime missing_assets and is not a catalog blocker; stage official weights when available.

Concrete EO-1 algorithm entry sourced from the EO official repository.

## Running in WorldFoundry

The catalog launch is `worldfoundry-eval run eo1 --pipeline.task-profile vla`. The command builder above switches `--pipeline.task-profile` among recorded tasks and still emits `worldfoundry-eval run`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Recorded weight repositories include `IPEC-COMMUNITY/EO-1-3B`. Stage assets with `bash scripts/inference/prepare_model_infer.sh eo1`.

Status: **Runner parity pending**.
