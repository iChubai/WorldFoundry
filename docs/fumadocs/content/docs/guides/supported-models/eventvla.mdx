EventVLA from InternRobotics is a long-horizon-memory VLA: on top of a Qwen3-VL-4B base it adds an event head, temporal anchors, and a raw keyframe-image memory so the policy remembers what already happened in long tasks. The default policy is the RoboTwin-MeM subfolder of the Apache-2.0 ganlinyang/EventVLA checkpoint collection.

## What it is for

`eventvla` maps camera observations and an instruction to an action trajectory.

Qwen3-VL encoding feeds action-token gathering and a checkpoint-compatible MLP action head; the event head plus temporal anchors maintain episodic structure while keyframe images form the memory. All components run in process. It is published by Shanghai AI Laboratory (InternRobotics).

Tasks: VLA, VLA action prediction, and VLA long horizon memory. Aliases: `event-vla` and `eventvla-robotwin-mem`.

Suggested benchmarks: [RoboTwin 2.0](/docs/evaluation/benchmark-hub/robotwin) (The RoboTwin-MeM checkpoint targets RoboTwin memory tasks).

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted); artifacts `action_trace` and `eventvla_action_trace.json`.

CLI task profiles: `default`. WorldFoundry binds `EventVLAPipeline`.

Family status: **Runner parity pending**.

Stage the EventVLA checkpoint (subfolder RoboTwin-MeM) and the Qwen3-VL-4B-Instruct base locally. Training, datasets, simulators, benchmark launchers, and WebSocket transport are excluded.

The released policy targets RoboTwin memory tasks; other suites need fine-tuning.

## Running in WorldFoundry

Run `wf run eventvla --pipeline.task-profile default` to predict actions.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8, torch>=2.6.0).

Weights: `ganlinyang/EventVLA` and `Qwen/Qwen3-VL-4B-Instruct`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh eventvla`. Add `--download` to fetch missing public checkpoints.
