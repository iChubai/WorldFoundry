FramePack is Stanford's **constant-memory** long image-to-video packer (ControlNet authors): input-frame context is packed into a **fixed-length** window so generation cost stays roughly constant as the clip grows, including minute-scale clips on modest VRAM. WorldFoundry runs a minimal infer-only runtime through `FramePackPipeline`.

## What it is for

Pack long video as next-frame chunks from a start image.

Launch `wf run framepack`.

Score on [ChronoMagic-Bench](/docs/evaluation/benchmark-hub/chronomagic-bench) — long-horizon generation suite matching FramePack's long-video focus.

## Runtime contract

Required: `prompt` and `image`; artifacts: `framepack.mp4`.

Official in-tree runner defaults, taken from the upstream UI quality recipe:

| Knob | Default |
| --- | --- |
| Duration | **5** s |
| FPS | **30** |
| Steps | **25** per FramePack section |
| Latent window | **9** |
| CFG / GS / RS | **1.0** / **10.0** / **0.0** |
| Seed | **31337** |
| TeaCache | **on** |

## Running in WorldFoundry

Status: **Runner parity pending**. Unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8). Stage `lllyasviel/FramePackI2V_HY` and `lllyasviel/FramePack_F1_I2V_HY_20250503` locally, then run `wf run framepack`. No VRAM requirement is recorded.
