Galaxea G0Plus 是星海图（Galaxea AI）的开放 VLA：输入 RGB、语言和状态，输出动作轨迹。发布的 checkpoint 基于 **PaliGemma-3B**，配备 **flow-matching** 动作采样器和 KV 缓存解码。WorldFoundry 把架构、KV cache、flow 采样器、严格 checkpoint 加载器、tokenizer 适配器、预处理和归一化都放在**树内**。checkpoint 恢复严格按照官方参数名对齐。运行时只接受本地就位资产，从不执行 checkpoint 自带的 Python。

发布的 G0Plus 基座面向**下游微调**，不声称是任务就绪策略。必须使用精确匹配的 `dataset_stats.json`——归一化过程不会虚构数值。

## 用来做什么

Galaxea / G0-VLA 策略路径：输入相机图像、指令与机器人状态，输出动作轨迹。

启动 `wf run galaxea-vla`。

## 运行时契约

必填 `image`、`prompt`、`state`；可选 `model_id`、`policy_family`；产物 `action_trace`、`galaxea_vla_action_trace.json`。

| 变体 | 相机 | 状态 / 动作 | 块 |
| --- | --- | --- | --- |
| `r1lite_mobile` | 3 | 21 / 26 | 32 |
| `r1lite_arm` | 3 | 14 / 14 | 32 |
| `libero` | 2 | 8 / 7 | 32 |

动作块是 **32** 步。就位的 transformer 在 `OpenGalaxea/G0-VLA` 的 `G0Plus_3B_base` 下。上表列出示例本体。

## 在 WorldFoundry 中运行

独立环境 `worldfoundry-vla-galaxea`（Python 3.11，CUDA 12.4+）。先把 `OpenGalaxea/G0-VLA`、`google/paligemma-3b-pt-224` 就位到本地，再在该环境执行 `wf run galaxea-vla`。
