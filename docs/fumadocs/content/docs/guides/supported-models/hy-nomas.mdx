## What it is for

`hy-nomas` is a text-to-video model: a prompt in, a video clip out.

A distilled Hy-Nomas DiT conditioned on a Qwen2.5-VL text backbone generates latent segments autoregressively with Euler scheduling and compressed KV history; the PixelUMM decoder turns the latents into frames. It is published by Tencent Hunyuan.

Tasks: text-to-video, action-conditioned video, and interactive world generation. Aliases: `hynomas` and `tencent/Hy-Nomas`. Modalities: text and action in, video out. Other variants: `hy-nomas-low-memory`.

## Runtime contract

Input `prompt` (bundled samples are used when omitted); options `frames`, `fps`, `height`, `width`, `steps`, and `guidance-scale`; artifact `hy-nomas.mp4`.

CLI task profile: `interactive-video`. WorldFoundry binds `HyNomasPipeline`. Defaults for `interactive-video`: frames=120, fps=24, height=720, width=1280, steps=8, guidance-scale=1.0.

Start with `hy-nomas`. The family has 2 variants, selectable in the command builder above: `hy-nomas` (`text-to-video`) — Runner parity pending; `hy-nomas-low-memory` (`text-to-video`) — Runner parity pending. Family status: **Runner parity pending**.

Ordered prompts are successive segments of one world. Use normalized camera-to-world matrices for explicit camera control. Stage the floating-point DiT, PixelUMM and Qwen2.5-VL-7B weights separately.

Generation with the full released checkpoints, low-memory quantization at deployed sizes, and Studio performance are not yet measured. Low-memory inference quantizes the floating-point checkpoints at load time (INT8/FP8); upstream packed INT8/FP8 export files are not supported.

## Running in WorldFoundry

It runs in the unified environment `worldfoundry-unified-cu121` (Python 3.11, CUDA 12.1).

Weights: `tencent/Hy-Nomas` and `Qwen/Qwen2.5-VL-7B-Instruct`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh hy-nomas`. Add `--download` to fetch missing public checkpoints.
