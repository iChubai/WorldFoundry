HyDRA is a camera-controlled video-to-video world model: it re-renders an input video along new camera behavior described by a camera JSON. Validated on the official example: a 50-step run generates a coherent 77-frame 832x480 continuation.

## What it is for

`hydra` conditions video generation on camera poses.

HyDRA pairs its own checkpoint (H-EmbodVis/HyDRA) with the Wan2.1-T2V-1.3B base model (Wan-AI/Wan2.1-T2V-1.3B).

Tasks: camera-controlled video, video-to-video, and world model. Aliases: `h-embodvis-hydra`. Modalities: video in, video out.

Suggested benchmarks: [CameraBench](/docs/evaluation/benchmark-hub/camerabench) (Camera-behavior adherence of re-rendered video).

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted); options `frames`, `fps`, `height`, `width`, `steps`, `seed`, and 1 more; artifacts `hydra.mp4`.

CLI task profiles: `default`. WorldFoundry binds `HydraPipeline`.

Family status: **Verified**.

Defaults for `default`: frames=77, fps=15, height=480, width=832, seed=42.

Bundled source is mandatory — external source checkouts are rejected. Inputs are prompt, video, and camera_json.

## Running in WorldFoundry

Generate a camera-controlled clip with `wf run hydra --pipeline.task-profile default`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Weights: `H-EmbodVis/HyDRA` and `Wan-AI/Wan2.1-T2V-1.3B`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh hydra`. Add `--download` to fetch missing public checkpoints.
