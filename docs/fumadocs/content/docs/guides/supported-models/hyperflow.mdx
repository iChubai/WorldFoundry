## What it is for

`hyperflow` covers text-to-video and image-to-video: a prompt and an optional still image in, a clip out. It is published by Video Rebirth.

Tasks: text-to-video, image-to-video, reference-to-video, and audio video generation. Aliases: `hyperflow-h3` and `minimax-h3-hyperflow`. Modalities: text and image in, video and audio out.

## Runtime contract

Input `prompt` (bundled samples are used when omitted); options `num-frames`, `seed`, and `memory-reserve-margin`; artifact `hyperflow.mp4`.

CLI task profiles: `t2va`, `fl2va`, and `ref2va`. WorldFoundry binds `HyperFlowPipeline`. Family status: **Runner parity pending**. Defaults for `t2va`, `fl2va`, and `ref2va`: num-frames=124, seed=42.

Supply a complete local diffusers MiniMax-H3 snapshot, `weights_path` and the dedicated Python executable. The upstream loader supplies the fixed grid; `num_inference_steps` must be 8 and output fps must be 24. Validated on a single H100: T2VA, single-image FL2VA, and image-reference Ref2VA generate 124 frames at 640×384 in eight steps, with full video and stereo audio decoding.

GPU inference requires substantial VRAM and host RAM; the upstream single-GPU measurements use an H200. The official frame count is aligned upward to `17n+5`, with supported aligned counts from 124 to 345 at 24 fps. Ref2VA requires `transformer_ref` weights; audio-only references are unsupported. High-resolution quality parity, multi-GPU inference, last-frame conditioning, and video/audio reference conditioning are not yet validated.

## Running in WorldFoundry

Generate a clip with `wf run hyperflow --pipeline.task-profile t2va`. Switch tasks in the command builder above to change `--pipeline.task-profile`.

It runs in the dedicated environment `hyperflow` (Python 3.11, CUDA 12.8, torch==2.11.0+cu128).

Weights: `videorebirth/hyperflow` and `MiniMaxAI/MiniMax-H3`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh hyperflow`. Add `--download` to fetch missing public checkpoints.
