It intentionally loads no model checkpoint — it is a renderer, not a generator.

## What it is for

Use `hyworld-worldgen` for catalog geometry inference. Choose it when the artifact is a reconstruction, not a generated video.

The unified runtime includes an in-tree torch point-splat fallback and does not require PyTorch3D. Official source is vendored at a pinned revision (license: tencent-hunyuan-community); this route is the official trajectory-render stage and does not claim full five-stage world generation. It is published by Tencent (Hunyuan).

Catalog tasks include camera-controlled-video, world-generation-stage, and point-cloud-rendering. Documented outputs include point cloud.

## Runtime contract

Required `image`, `camera_json`, and `scene_path`; artifacts `hyworld-worldgen.mp4`.

Recorded task profiles: `camera-controlled-video`, `world-generation-stage`, and `point-cloud-rendering`. WorldFoundry binds `HYWorld2WorldgenPipeline`.

Family status: **Runner parity pending**.

Provide an image, camera JSON, and a scene_path pointing at a pre-materialized HY-World scene. Scene materialization belongs to the separate full HY-World generation pipeline.

## Running in WorldFoundry

Launch `worldfoundry-eval run hyworld-worldgen --pipeline.task-profile camera-controlled-video` to write geometry. The command builder above switches `--pipeline.task-profile` among recorded tasks and still emits `worldfoundry-eval run`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

No public checkpoint id is recorded on this card; follow the usage notes for staging. Stage assets with `bash scripts/inference/prepare_model_infer.sh hyworld-worldgen`.
