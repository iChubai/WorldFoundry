LiveWorld is a camera-controlled video-to-video world model with a monitor-centric workflow: it consumes a video plus a geometry NPZ and re-renders the scene under new camera behavior. WorldFoundry runs the official source with a dedicated geometry-NPZ input route.

## What it is for

`liveworld` generates camera-controlled video: a camera trajectory in, a clip that follows it out.

LiveWorld adds its own LoRA and state adapter (ZichengD/LiveWorld) to the Wan2.1-T2V-14B base model, and uses Qwen3-VL-8B-Instruct for entity detection, SAM3 for segmentation, STream3R for reconstruction, and DINOv3 for matching.

Tasks: camera-controlled video, video-to-video, and world model. Modalities: video in, video out.

Suggested benchmarks: [CameraBench](/docs/evaluation/benchmark-hub/camerabench) (Camera-behavior adherence of re-rendered video).

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted); artifacts `liveworld.mp4`.

CLI task profiles: `default`. WorldFoundry binds `LiveWorldPipeline`.

Family status: **Runner parity pending**.

Inputs are prompt, video, and geometry_npz. Stage all six checkpoint snapshots locally before running: ZichengD/LiveWorld, Wan2.1-T2V-14B, Qwen3-VL-8B-Instruct, SAM3, STream3R, and DINOv3.

Needs a geometry NPZ alongside the video input.

## Running in WorldFoundry

Generate a camera-controlled clip with `wf run liveworld --pipeline.task-profile default`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Weights: `ZichengD/LiveWorld`, `Wan-AI/Wan2.1-T2V-14B`, and `Qwen/Qwen3-VL-8B-Instruct` among others. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh liveworld`. Add `--download` to fetch missing public checkpoints.
