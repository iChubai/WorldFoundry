WorldFoundry runs LTX-2 and LTX-2.3 T2V, I2V and IC-LoRA V2V in-process on the
canonical LTX components. The six public variants share the native diffusion
assembler, transformer, Gemma text encoder, audio/video codecs, spatial
upsampler and joint multi-stage runner.

## Runtime contract

| Variant | Input | Environment |
| --- | --- | --- |
| `ltx-2-t2v`, `ltx-2.3-t2v` | Text prompt | `worldfoundry-unified-cu128` |
| `ltx-2-i2v`, `ltx-2.3-i2v` | Prompt and reference image | `worldfoundry-unified-cu128` |
| `ltx-2-v2v` | Prompt and **pose control video** | `ltx-2.5` |
| `ltx-2.3-v2v` | Prompt and **Canny, depth or pose control video** | `ltx-2.5` |

V2V requires an explicit `control_type` and a version-matched IC-LoRA. Arbitrary
RGB footage is not a control video; images are rejected. The public bindings
remain `LTX2V2VPipeline` and `LTX23V2VPipeline`.

The IC-LoRA recipe uses eight first-stage steps with adapter weights and encoded
reference-video tokens. It then upsamples and performs three refinement steps
with clean base weights. `skip_stage_2=True` returns the first-stage video at
half the requested height and width. This matches the IC-LoRA inference path at
`a95ab856bf29407b6b066ede0abe1846050db56c`.

V2V defaults are 512×768, 121 frames, 24 fps, seed 171198, and control/LoRA
strength 1.0. Height and width must be multiples of 64 and at least 128; frame
count must be `8n+1` and at least 9. `control_strength` is in `[0, 1]`;
`lora_strength` is positive. Offload choices are `none`, `cpu` and `disk`.
Inference uses BF16 weights. The shared media writer emits H.264 video with AAC
audio, plus a `.ltx.log` execution log.

## Running in WorldFoundry

V2V uses the existing `ltx-2.5` environment: Python 3.11, CUDA 12.8, Torch 2.11
and Transformers 5.x. Its canonical split-Gemma loader requires the newer
Transformers processor API. T2V/I2V keep their existing unified environment and
Gemma loading path. Direct Python calls run in the active model environment;
CLI and Studio use the declared runtime profile.

```bash
bash scripts/inference/prepare_model_infer.sh ltx-2-v2v
wf run ltx-2-v2v \
  --pipeline.prompt "A dancer moves across the stage." \
  --pipeline.input-path /path/to/pose-control.mp4 \
  --pipeline.control-type pose \
  --pipeline.height 256 --pipeline.width 256 \
  --pipeline.num-frames 17 --pipeline.offload cpu \
  --output-dir outputs/ltx-2-v2v
```

For LTX-2.3, select `ltx-2.3-v2v` and the matching control type. Stage the
following assets before inference; `prepare_model_infer.sh --download` can
acquire declared checkpoints after accepting their terms.

- LTX-2: `ltx-2-19b-distilled.safetensors`,
  `ltx-2-spatial-upscaler-x2-1.0.safetensors`, and
  `ltx-2-19b-ic-lora-pose-control.safetensors`.
- LTX-2.3: `ltx-2.3-22b-distilled-1.1.safetensors`,
  `ltx-2.3-spatial-upscaler-x2-1.1.safetensors`, and
  `ltx-2.3-22b-ic-lora-union-control-ref0.5.safetensors`.
- A complete local `google/gemma-3-12b-it-qat-q4_0-unquantized` directory,
  including weights, configuration, tokenizer and processor files.

The loading options are `checkpoint_path`, `spatial_upsampler_path`,
`ic_lora_path` and `gemma_root`. Adapted IC-LoRA source is covered by the
LTX-2.x Community License recorded in `THIRD-PARTY-NOTICES`; checkpoint and
Gemma terms also apply.

## Validation and limitations

Released checkpoint headers map bijectively to the native inference components,
including all 960 keys in each IC-LoRA. Tiny FP32 comparisons in the `ltx-2.5`
environment match the pinned upstream adapter fusion, reference conditioning,
both denoising stages and audio/video decode exactly, with and without
refinement. Existing T2V/I2V and LTX-2.5 no-regression comparisons are also exact.

Released-weight GPU/MPS replay, accelerator offload behavior, dynamic-motion
quality and default-resolution V2V quality remain pending. Small random-weight
parity is not checkpoint-backed quality validation. I2V retains its separately
recorded 8+3 versus 8+4 documentation discrepancy and configuration-specific
Studio demo evidence.

[AIGCBench](/docs/evaluation/benchmark-hub/aigcbench) is the recorded I2V
benchmark entry point, not an ingested score.
