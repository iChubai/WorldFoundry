WorldFoundry 在进程内使用规范 LTX 组件运行 LTX-2 与 LTX-2.3 的 T2V、I2V 和
IC-LoRA V2V。六个公开变体共用原生 diffusion assembler、Transformer、Gemma
文本编码器、音视频编解码器、空间上采样器和联合多阶段 runner。

## 运行时契约

| 变体 | 输入 | 环境 |
| --- | --- | --- |
| `ltx-2-t2v`、`ltx-2.3-t2v` | 文本提示词 | `worldfoundry-unified-cu128` |
| `ltx-2-i2v`、`ltx-2.3-i2v` | 提示词与参考图像 | `worldfoundry-unified-cu128` |
| `ltx-2-v2v` | 提示词与**姿态控制视频** | `ltx-2.5` |
| `ltx-2.3-v2v` | 提示词与 **Canny、深度或姿态控制视频** | `ltx-2.5` |

V2V 必须显式指定 `control_type` 并使用版本匹配的 IC-LoRA。普通 RGB 视频不是
控制视频；图像输入会被拒绝。公开绑定保持为 `LTX2V2VPipeline` 和
`LTX23V2VPipeline`。

IC-LoRA 配方在第一阶段使用适配器权重和编码后的参考视频 token，执行八步去噪；
随后上采样，并使用未融合适配器的基座权重执行三步细化。
`skip_stage_2=True` 返回第一阶段的视频，高和宽均为请求值的一半。
该流程对应 `a95ab856bf29407b6b066ede0abe1846050db56c` 的 IC-LoRA 推理路径。

V2V 默认参数为 512×768、121 帧、24 fps、seed 171198，控制强度和 LoRA 强度
均为 1.0。高和宽必须至少为 128 且能被 64 整除；帧数必须满足 `8n+1` 且至少为 9。
`control_strength` 范围为 `[0, 1]`，`lora_strength` 必须为正数。
卸载选项为 `none`、`cpu` 和 `disk`。推理使用 BF16 权重。
共享媒体写入器输出 H.264 视频与 AAC 音频，并写入 `.ltx.log` 执行日志。

## 在 WorldFoundry 中运行

V2V 使用现有 `ltx-2.5` 环境：Python 3.11、CUDA 12.8、Torch 2.11 和
Transformers 5.x。规范 split-Gemma 加载器需要新版 Transformers processor API。
T2V/I2V 保持现有统一环境与 Gemma 加载路径。直接 Python 调用使用当前模型环境，
CLI 和 Studio 使用声明的 runtime profile。

```bash
bash scripts/inference/prepare_model_infer.sh ltx-2-v2v
wf run ltx-2-v2v \
  --pipeline.prompt "A dancer moves across the stage." \
  --pipeline.input-path /path/to/pose-control.mp4 \
  --pipeline.control-type pose \
  --pipeline.height 256 --pipeline.width 256 \
  --pipeline.num-frames 17 --pipeline.offload cpu \
  --output-dir outputs/ltx-2-v2v
```

使用 LTX-2.3 时选择 `ltx-2.3-v2v` 和对应的控制类型。推理前准备以下资产；
接受相应条款后，可通过 `prepare_model_infer.sh --download` 获取声明的权重。

- LTX-2：`ltx-2-19b-distilled.safetensors`、
  `ltx-2-spatial-upscaler-x2-1.0.safetensors` 和
  `ltx-2-19b-ic-lora-pose-control.safetensors`。
- LTX-2.3：`ltx-2.3-22b-distilled-1.1.safetensors`、
  `ltx-2.3-spatial-upscaler-x2-1.1.safetensors` 和
  `ltx-2.3-22b-ic-lora-union-control-ref0.5.safetensors`。
- 完整的本地 `google/gemma-3-12b-it-qat-q4_0-unquantized` 目录，包含权重、
  配置、tokenizer 和 processor 文件。

加载参数为 `checkpoint_path`、`spatial_upsampler_path`、`ic_lora_path` 和
`gemma_root`。改编的 IC-LoRA 源码适用 `THIRD-PARTY-NOTICES` 中记录的
LTX-2.x Community License；权重与 Gemma 的条款也同样适用。

## 验证与限制

LTX-2 与 LTX-2.3 的 I2V 路径已生成非空 demo 视频；已记录的 V2V 运行使用 256px 合成姿态/Canny 控制输入。T2V 变体尚未完成发布权重验证。I2V 的空间上采样器从 `spatial_upsampler_path` 自动加载，不是独立的 Studio 细化开关。

发布权重 header 与原生推理组件之间的映射为双射，包括每个 IC-LoRA 的全部
960 个键。在 `ltx-2.5` 环境中进行的小尺寸 FP32 对照中，适配器融合、参考条件、
两个去噪阶段与音视频解码均与固定版本上游精确一致，覆盖启用和跳过细化两种情况。
现有 T2V/I2V 与 LTX-2.5 的无回归对照也精确一致。

发布权重 GPU/MPS 回放、加速器卸载行为、动态运动质量与默认分辨率 V2V 质量
仍待验证。小尺寸随机权重一致性不等同于发布权重的质量验证。I2V 仍保留独立记录的
8+3 与文档 8+4 调度差异，以及仅覆盖特定配置的 Studio demo 证据。

[AIGCBench](/zh/docs/evaluation/benchmark-hub/aigcbench) 是记录的 I2V 评测入口，
不是已摄入分数。
