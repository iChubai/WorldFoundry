Luma Ray2 is Luma AI's hosted video generation model for text-to-video and image-to-video. WorldFoundry's Studio pipeline wraps the Luma API so a prompt or a start frame turns into a downloadable clip inside the normal WorldFoundry result layout. The model runs on Luma's servers, not locally.

## What it is for

`luma-ray2` runs on the provider's hosted API; no local checkpoint is needed.

Tasks: text-to-video, image-to-video, and hosted api. Modalities: text and image in, video out.

Suggested benchmarks: [VBench](/docs/evaluation/benchmark-hub/vbench) (Standard multi-dimension quality suite for comparing hosted text/image-to-video outputs), [Physics-IQ Original](/docs/evaluation/benchmark-hub/physics-iq) (Probes whether provider-side video models respect basic physical plausibility).

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted).

CLI task profiles: `default`. WorldFoundry binds `LumaRay2Pipeline`.

Supply your own Luma account and API key through LUMA_API_KEY (or LUMALABS_API_KEY); keys are issued through Luma's developer platform (lumalabs.ai). No weights are downloaded and no local GPU is needed — generation happens on the provider side, so cost, quota, and content policy follow your provider account.

Requires a paid provider account and API key; WorldFoundry does not ship credentials.

The provider controls model versioning, so outputs can change over time.

## Running in WorldFoundry

Call the hosted model with `wf run luma-ray2 --pipeline.task-profile default`.

No runtime environment is recorded for this model.

Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh luma-ray2`. Add `--download` to fetch missing public checkpoints.
