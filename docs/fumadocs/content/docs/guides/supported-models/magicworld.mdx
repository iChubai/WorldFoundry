## What it is for

`magicworld` generates camera-controlled video: a camera trajectory in, a clip that follows it out.

Builds on Wan2.1-Fun-V1.1-1.3B-InP with Apple DepthPro for metric depth; the LuckyLiGY/MagicWorld checkpoint provides the MagicWorld-Fast and MagicWorld-Base weights. Licensing is split: code is apache-2.0, while the upstream README applies CC BY-NC-SA 4.0 terms to released model materials. It is published by vivo (Camera Research).

Tasks: interactive world model, camera-controlled video, and image-to-video. Modalities: image in, video out.

Suggested benchmarks: [CameraBench](/docs/evaluation/benchmark-hub/camerabench) (Camera-control adherence of interactive rollouts).

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted); options `frames`, `seed`, and `native-rows`; artifacts `magicworld.mp4`.

CLI task profiles: `default`. WorldFoundry binds `MagicWorldPipeline`.

Family status: **Runner parity pending**.

Defaults for `default`: frames=81, seed=42.

Inputs are prompt, image, and native_rows camera control. Stage LuckyLiGY/MagicWorld (ModelScope, about 16 GB), alibaba-pai/Wan2.1-Fun-V1.1-1.3B-InP, and apple/DepthPro (ModelScope) before running.

## Running in WorldFoundry

Run `wf run magicworld --pipeline.task-profile default` to follow the camera path.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Weights: `LuckyLiGY/MagicWorld`, `alibaba-pai/Wan2.1-Fun-V1.1-1.3B-InP`, and `apple/DepthPro`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh magicworld`. Add `--download` to fetch missing public checkpoints.
