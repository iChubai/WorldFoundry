Metric3D recovers metric-scale depth from a single image by normalizing images into a canonical camera space, which lets one model generalize across cameras. WorldFoundry uses it as a metric-depth prior, and it is the default metric-depth model in the ViPE SLAM configuration.

## What it is for

Use `metric3d-prior` to predict depth maps from the input images.

Per the upstream publication (ICCV 2023), a canonical-camera transformation resolves the metric ambiguity of single-image depth. The checkpoint is JUGGHM/Metric3D under a bsd-2-clause license. It is published by DJI / Zhejiang University.

Tasks: monocular depth estimation, metric depth estimation, and geometry prior. Aliases: `metric3d` and `yvanyin-metric3d`. Modalities: image in, depth out.

## Runtime contract

Inputs `input-path` (bundled samples are used when omitted); options `model`, `version`, `focal-length`, `execute`, and `max-points`; artifacts `metric3d-prior.npz`.

CLI task profiles: `default`. WorldFoundry binds `Metric3DPriorPipeline`.

Family status: **Verified**.

Pass one image as input_path and, when known, its focal_length; the run writes the depth prediction to metric3d-prior.npz.

Metric accuracy depends on camera-intrinsics quality; wrong intrinsics degrade the scale.

## Running in WorldFoundry

Estimate depth with `wf run metric3d-prior --pipeline.task-profile default`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Weights: `JUGGHM/Metric3D`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh metric3d-prior`. Add `--download` to fetch missing public checkpoints.
