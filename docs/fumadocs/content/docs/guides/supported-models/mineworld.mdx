MineWorld is Microsoft's real-time open-source interactive world model for Minecraft: an autoregressive transformer that plays forward Minecraft scenes from image/video context and actions (arXiv 2504.08388, MIT license). Running it requires the official dependency environment, checkpoints, and validation/demo data.

## What it is for

`mineworld` generates future frames conditioned on actions.

Per the paper, a visual tokenizer plus an autoregressive transformer over interleaved state-action tokens, with parallel decoding for real-time speed.

Tasks: interactive world model, minecraft world model, and action-conditioned video.

Suggested benchmarks: [WorldModelBench](/docs/evaluation/benchmark-hub/worldmodelbench) (Action-conditioned game-world rollout quality).

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted); options `interactions`, `frames`, `fps`, and `seed`; artifacts `mineworld.mp4`.

CLI task profiles: `interactive-video`. WorldFoundry binds `MineWorldPipeline`.

Family status: **Runner parity pending**.

Defaults for `interactive-video`: frames=16, fps=16, seed=42.

Stage the official checkpoints and validation data first; until they are present, the pipeline returns blocked runtime diagnostics instead of a video.

## Running in WorldFoundry

Run `wf run mineworld --pipeline.task-profile interactive-video` to roll out the world model.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

No public checkpoint is listed for this model; stage the weights as described in the usage notes. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh mineworld`. Add `--download` to fetch missing public checkpoints.
