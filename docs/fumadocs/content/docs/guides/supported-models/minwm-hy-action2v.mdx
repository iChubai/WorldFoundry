minWM HY Action2V is Shengshu's minimal world-model recipe on a HunyuanVideo-1.5 base: given a prompt, an image, and a motion trajectory it generates action-conditioned, camera-controllable video through a distilled DMD entrypoint.

## What it is for

`minwm-hy-action2v` conditions video generation on camera poses.

The official source is Apache-2.0. Only the HY15/Action2V/dmd subset of the 384.97 GB upstream minWM repository is required; you do not need the full research archive.

Tasks: interactive world model, action-conditioned video, and camera-controlled video. Aliases: `minwm` and `minwm-hy-action2v`.

Suggested benchmarks: [CameraBench](/docs/evaluation/benchmark-hub/camerabench) (Camera/motion-trajectory adherence).

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted); options `frames`, `fps`, `height`, `width`, `steps`, `seed`, and 1 more; artifacts `minwm-hy-action2v.mp4`.

CLI task profiles: `default`. WorldFoundry binds `MinWMHYAction2VPipeline`.

Family status: **Runner parity pending**.

Inputs are prompt, image, and trajectory (native motion tokens). Stage the HY15 Action2V DMD subset before running. For the Wan-based variant use `minwm-wan-action2v`.

## Running in WorldFoundry

Run `wf run minwm-hy-action2v --pipeline.task-profile default` to follow the camera path.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Weights: `MIN-Lab/minWM` and `tencent/HunyuanVideo-1.5`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh minwm-hy-action2v`. Add `--download` to fetch missing public checkpoints.
