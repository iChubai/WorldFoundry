## 用来做什么

需要 catalog 上的 VLA 策略时选 `perceptual-framesamp-modul`：指令与观测进、动作轨迹出。用来滚动已记录策略，不是用来训练新策略。

仓库记录的设计将感知帧采样模块与策略学习及可选的 VLM 子目标预测器结合。解析器、运行时导入与 compileall 检查无需外部 checkout 即通过；更多内部细节仓库未记录。

catalog 记录的任务包括 视觉-语言-动作（VLA）、VLA 动作预测、VLA 策略执行、具身评测。别名包括 `mme_vla`、`robomme-policy-learning`、`perceptual-framesamp-modul`。

记录的评测入口包括[RoboMME](/zh/docs/evaluation/benchmark-hub/robomme)（RoboMME 项目的原生基准）。

## 运行时契约

必填 `image`、`prompt`、`state`；可选 `model_id` (mme-vla)、`image_keys` (observation/image, observation/wrist_image)、`state_key` (observation/state)、`memory_keys` (static_image_emb, static_pos_emb, static_state_emb, static_mask, recur_image_emb, recur_pos_emb, recur_state_emb, recur_mask, simple_subgoal, grounded_subgoal)、`policy_family`；产物 `action_trace`、`mme-vla_action_trace.json`。

记录的任务 profile：`vla`、`vla.action_prediction`、`vla.policy_rollout`、`embodied_benchmark`。绑定的 pipeline 类是 `MMEVLAPipeline`。

系列状态：**仅静态加载**。

在声称 demo parity 前仍需 checkpoint 驱动的动作块验证；请先就位帧采样模块 checkpoint。

尚未声称 demo parity；checkpoint 驱动验证待完成。

## 在 WorldFoundry 中运行

catalog 启动命令是 `worldfoundry-eval run perceptual-framesamp-modul --pipeline.task-profile vla.policy_rollout`。上方命令构建器按已记录任务切换 `--pipeline.task-profile`，发出的仍是 `worldfoundry-eval run`。

运行环境是统一 profile `worldfoundry-unified-cu128`（Python 3.11，CUDA 12.8，torch==2.7.1）。

记录的权重仓库包括 `Yinpei/perceptual-framesamp-modul`、`Yinpei/mme_vla_suite`、`Yinpei/pi05_baseline` 等。就位权重用 `bash scripts/inference/prepare_model_infer.sh perceptual-framesamp-modul`。
