MolmoBot is AI2's robot policy family. WorldFoundry exposes the OLMo-based action-chunk route and the separate Pi0-DROID joint-position route through in-tree inference-only pipelines.

See [arXiv 2603.16861](https://arxiv.org/abs/2603.16861), the [project page](https://allenai.github.io/MolmoBot), and the [official repository](https://github.com/allenai/MolmoBot).

## Validated variants

The released `MolmoBot-DROID` and `MolmoBot-Img-DROID` checkpoints run offline GPU action inference on a real DROID observation with two cameras and robot state. For `MolmoBot-Pi0-DROID`, `MolmoBotPipeline` prepares the same camera, state, and prompt inputs as the official `PiJointPosPolicy` and returns finite 7D arm and 1D gripper actions; values differ between runs because sampling is stochastic.

The OLMo-based DROID checkpoints are Apache-2.0. The Pi0-DROID checkpoint is [Gemma-licensed](https://huggingface.co/allenai/MolmoBot-Pi0-DROID). `MolmoBot-RBY1Multitask` is available but has not been validated.

## Runtime contract

Supply a task prompt, the `exo_camera_1` and `wrist_camera` images, and matching robot state. For Pi0-DROID, the verified state has seven arm joint positions plus a two-value gripper state; the output contains arm `(7,)` and gripper `(1,)` actions. Select the Pi0 route with `MolmoBotPipeline.from_pretrained(..., variant="pi0_droid")`, using the released `allenai/MolmoBot-Pi0-DROID` checkpoint. It requires the pinned isolated OpenPI dependencies and PaliGemma tokenizer. The in-tree public adapter does not load the MolmoSpaces simulator.

## Limitations

Validation covers offline checkpoint loading, observation preparation, and action inference. The real DROID observation is outside the simulation-trained Pi0 policy's training distribution. No closed-loop robot execution, task-success rate, or semantic action quality has been measured.
