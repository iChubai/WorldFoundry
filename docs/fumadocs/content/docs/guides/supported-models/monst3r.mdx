MonST3R extends the DUSt3R pointmap approach to dynamic scenes: it estimates per-timestep geometry directly from video, recovering shape and motion without a static-scene assumption. Validated on CUDA through Studio: the pipeline writes a valid GLB scene with 51 geometries and finite point data.

## What it is for

`monst3r` recovers 3D geometry from images: views in, a reconstruction, camera trajectory, or point cloud out.

Per the upstream publication, MonST3R fine-tunes the DUSt3R pointmap regressor on dynamic data so that pointmaps are estimated per timestep; downstream optimization aligns them into a 4D scene. WorldFoundry writes the result as a GLB scene. It is published by Google DeepMind / UC Berkeley.

Tasks: geometry estimation in the presence of motion.

## Runtime contract

Inputs `input-path` (bundled samples are used when omitted); options `weights`, `seq-name`, `niter`, `flow-loss-weight`, `skip-pair-dynamic-mask`, `silent`, and 1 more; artifacts `generated_4d_scene` and `monst3r.glb`.

CLI task profiles: `default`. WorldFoundry binds `MonST3RPipeline`.

Family status: **Verified**.

The Studio default disables the optional flow loss so missing RAFT2/SAM2 assets do not block preview output. For full official dynamic-mask parity, configure the MonST3R, RAFT, and SAM2 assets in the runtime environment.

Full official dynamic-mask parity needs RAFT2/SAM2 assets beyond the Studio default path.

## Running in WorldFoundry

Reconstruct the scene with `wf run monst3r --pipeline.task-profile default`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

No public checkpoint is listed for this model; stage the weights as described in the usage notes. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh monst3r`. Add `--download` to fetch missing public checkpoints.
