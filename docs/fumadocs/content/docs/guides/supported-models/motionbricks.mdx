MotionBricks is part of NVIDIA's GR00T-WholeBodyControl stack: it generates humanoid whole-body motion — the action side of embodied world modeling, emitting action traces rather than video (paper arXiv 2604.24833).

## What it is for

Use `motionbricks` to step a world forward with actions and render the resulting frames.

WorldFoundry runs the official Apache-2.0 MotionBricks source from the GR00T-WholeBodyControl repository at a pinned commit and returns an action_trace artifact.

Tasks: human action generation, motion generation, and world model.

## Runtime contract

Artifacts `action_trace` and `motionbricks_runtime_plan.json`.

CLI task profiles: `default`. WorldFoundry binds `MotionBricksPipeline`.

Family status: **Runner parity pending**.

Place the official source at $\{WORLDFOUNDRY_MODEL_SOURCE_DIR\}/GR00T-WholeBodyControl/motionbricks and stage the MotionBricks checkpoints and robot assets. Until they are staged, a run writes a runtime plan (motionbricks_runtime_plan.json) that lists the missing assets instead of generating motion.

Emits action traces, not video artifacts.

## Running in WorldFoundry

Step the world with `wf run motionbricks --pipeline.task-profile default`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

No public checkpoint is listed for this model; stage the weights as described in the usage notes. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh motionbricks`. Add `--download` to fetch missing public checkpoints.
