Multi-task DiT Policy 是模仿学习的扩散 transformer 策略，以 LeRobot 中具体的 multi_task_dit 实现为参考记录——上游未识别到独立官方仓库。WorldFoundry 通过树内动作运行时适配器路由；未记录 checkpoint，运行输出运行时计划。

## 用来做什么

需要 catalog 上的 VLA 策略时选 `multi-task-dit`：指令与观测进、动作轨迹出。用来滚动已记录策略，不是用来训练新策略。

以多任务上下文为条件的 DiT（扩散 transformer）策略头，遵循 LeRobot 参考实现。更多内部细节仓库未记录。该模型由Hugging Face（LeRobot 参考实现）发布。

catalog 记录的任务包括 模仿学习、diffusion_transformer_policy、机器人策略。别名包括 `multi_task_dit`、`multitask-dit-policy`。

Multi-task DiT 模仿策略——出动作轨迹，不是视频。

## 运行时契约

必填 `image`、`prompt`、`state`；可选 `model_id` (multi-task-dit)、`policy_family`、`action_representation`；产物 `action_trace`、`multi-task-dit_action_trace.json`。

记录的任务 profile：`imitation_learning`、`diffusion_transformer_policy`、`robot_policy`。绑定的 pipeline 类是 `MultiTaskDiTPipeline`。

系列状态：**Runner 一致性待确认**。

checkpoint 缺失由运行时 missing_assets 报告，不视为 catalog 阻塞；权重就位前运行输出运行时计划。 就位训练好的策略 checkpoint 即可运行真实预测。

参考实现条目：无独立官方仓库或权重。

## 在 WorldFoundry 中运行

catalog 启动命令是 `worldfoundry-eval run multi-task-dit --pipeline.task-profile imitation_learning`。上方命令构建器按已记录任务切换 `--pipeline.task-profile`，发出的仍是 `worldfoundry-eval run`。

运行环境是统一 profile `worldfoundry-unified-cu128`（Python 3.11，CUDA 12.8）。

记录的权重仓库包括 `lerobot/multi_task_dit`。就位权重用 `bash scripts/inference/prepare_model_infer.sh multi-task-dit`。

状态：**Runner 一致性待确认**。
