MVDiffusion generates multi-view images and panoramas with correspondence-aware attention. In WorldFoundry, the image-outpainting route turns one input image into eight views and a panorama; generated regions can show visible consistency defects.

## What it is for

`mvdiffusion` recovers 3D geometry from images: views in, a reconstruction, camera trajectory, or point cloud out.

Per the NeurIPS 2023 paper (arXiv 2307.01097), parallel diffusion-model branches generate all views simultaneously with correspondence-aware attention keeping them globally consistent. It is published by Simon Fraser University.

Tasks: correspondence-aware multiview image generation and scene texturing. Aliases: `MVDiffusion: Enabling Holistic Multi-view Image Generation`.

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted); options `steps`, `gen-video`, and `python-executable`; artifact `mvdiffusion.png`.

CLI task profile: `default`. WorldFoundry binds `MVDiffusionPipeline`. Family status: **Runner parity pending**. Defaults for `default`: steps=20.

Provide one image for the outpainting route. The default artifact is a panorama PNG.

Generated wall regions and objects can diverge visibly from the input scene across views. The optional spin video and full upstream parity are not validated. Panorama-oriented training: free-form camera trajectories are out of scope.

Stage the upstream source checkout and checkpoints locally before running; without them the run cannot produce multi-view output.

## Running in WorldFoundry

Reconstruct the scene with `wf run mvdiffusion --pipeline.task-profile default`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

No public checkpoint is listed for this model; stage the weights as described in the usage notes. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh mvdiffusion`. Add `--download` to fetch missing public checkpoints.
