MVDiffusion generates consistent multi-view images in one shot — panoramas from text or perspective views, and texture views for scenes — by letting diffusion branches attend to each other. In WorldFoundry, the image-outpainting route turns one input image into eight views and a panorama PNG.

## What it is for

`mvdiffusion` recovers 3D geometry from images: views in, a reconstruction, camera trajectory, or point cloud out.

Per the NeurIPS 2023 paper (arXiv 2307.01097), parallel diffusion-model branches generate all views simultaneously with correspondence-aware attention keeping them globally consistent. It is published by Simon Fraser University.

Tasks: correspondence-aware multiview image generation and scene texturing. Aliases: `MVDiffusion: Enabling Holistic Multi-view Image Generation`.

## Runtime contract

Required `prompt` and `image`; optional `video` and `actions`; artifacts `generated_3d_asset` and `mvdiffusion.png`.

CLI task profiles: `default`. WorldFoundry binds `MVDiffusionPipeline`.

Family status: **Runner parity pending**.

Stage the upstream source checkout and checkpoints locally before running; without them the run cannot produce multi-view output.

Generated wall regions and objects can diverge visibly from the input scene across views.

## Running in WorldFoundry

Reconstruct the scene with `wf run mvdiffusion --pipeline.task-profile default`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

No public checkpoint is listed for this model; stage the weights as described in the usage notes. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh mvdiffusion`. Add `--download` to fetch missing public checkpoints.
