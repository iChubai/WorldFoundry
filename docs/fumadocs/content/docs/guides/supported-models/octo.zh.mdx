Octo 是伯克利 RAIL 的 transformer 通用机器人策略，带扩散动作头，实现是 JAX / Flax。官方论文是 [Octo: An Open-Source Generalist Robot Policy](https://arxiv.org/abs/2405.12213)（arXiv 2405.12213）。项目页：[octo-models.github.io](https://octo-models.github.io/)。代码在 [octo-models/octo](https://github.com/octo-models/octo)。

<ModelPaperFigures modelId="octo" locale="zh" />

WorldFoundry 用自有推理代码运行 Octo，无需上游 checkout。两个 variant 共用这套代码：`octo-base-1.5` 与 `octo-small-1.5`。已在 A100 上用官方 **octo-small-1.5** checkpoint 验证：Orbax 树可恢复（**136,670,604** 参数），`sample_actions` 返回有限的 **(1, 4, 7)** 动作块。`octo-base-1.5` 的采样尚未验证。

## 用来做什么

要跑已在 GPU 上验证的路径，从 `octo-small-1.5` 开始。必填 `image`、`instruction`、`prompt`、`video`。`OctoPipeline` 写出 `octo_action_trace.json`。默认运行时配置固定 `variant=small`、`dataset_key=bridge_dataset`、`image_key=image_primary`。

`octo-base-1.5` 使用同一建模代码和自己的 Hugging Face checkpoint。Open-X 通用策略的常见评测场是 [SimplerEnv](/zh/docs/evaluation/benchmark-hub/simpler-env)。真实 rollout 仍需要按 benchmark 绑定动作空间。

## 运行时契约

图像缩到 **256×256**。已验证的 small 策略块是 **batch 1 × 动作视野 4 × 动作维 7**。策略旁声明的文本资产：CLIP processor 在 `${WORLDFOUNDRY_HFD_ROOT}/openai--clip-vit-base-patch32`，本地多语言句向量在 `${WORLDFOUNDRY_CKPT_DIR}/octo/universal-sentence-encoder-multilingual-3`。

## 在 WorldFoundry 中运行

独立环境 `worldfoundry-octo-jax`（Python 3.10，CUDA 11.8，JAX 0.4.20，cuDNN 8.9）。这不是 PyTorch 统一栈。启动已 GPU 验证的 variant：

```
wf run octo-small-1.5
```

命令构建器的默认启动使用 `octo-base-1.5`；要跑已验证的路径，换成 `octo-small-1.5`。许可证未注明——生产使用前请确认上游条款。
