## What it is for

Pick `omnivinci` for the recorded multimodal reasoning route: documented inputs in, a reasoning artifact out. Use it when the card is a reasoner, not a generator.

OmniVinci combines a Qwen2 causal decoder, a Dynamic-S2 SigLIP vision tower and a Qwen2Audio encoder with temporal pooling and rotary embeddings. WorldFoundry packages the Apache-2.0 inference glue from nvidia/omnivinci revision 7b3777b and loads native Transformers backbones from local checkpoint data.

Catalog tasks include multimodal-reasoning, audio-reasoning, image-question-answering, and video-question-answering. Catalog aliases include `nvidia/omnivinci`.

## Runtime contract

Optional `prompt`, `image`, `video`, `seed`, and `frames`; artifacts `omnivinci.json`.

CLI task profiles: `multimodal-reasoning`, `audio-reasoning`, `image-question-answering`, `video-question-answering`, and `video_generation`. WorldFoundry binds `OmniVinciPipeline`.

Family status: **Runner parity pending**.

Use it to ask questions about images and videos, rather than to generate content. Video requests default to 8 frames (max_video_frames accepts 1–128); load_audio_in_video is false by default. The local checkpoint must include its llm, vision_tower, sound_tower and both projector directories, tokenizer data and qwen2.jinja.

The in-tree processor and model load the released local component layout; missing checkpoint/assets are reported at runtime.

## Running in WorldFoundry

Launch `wf run omnivinci --pipeline.task-profile multimodal-reasoning` to run the reasoning route. The command builder above switches `--pipeline.task-profile` among recorded tasks and still emits `wf run`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Recorded weight repositories include `nvidia/omnivinci`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh omnivinci`. Add `--download` to fetch missing public checkpoints.
