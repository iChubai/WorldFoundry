## 用来做什么

`open-dreamer` 是动作条件世界模型：输入动作和起始帧，输出推演结果。

WorldFoundry 适配器解析就位的检出、检查就位条件并构造官方 inference.py 命令。WorldFoundry 交互 token 被渲染为 Minecraft/VPT 动作 JSONL，使共享的世界模型调用面驱动 Dreamer 4 的动作空间。

任务：交互式世界模型、Minecraft 世界模型、动作条件视频、diffusion-world-model。别名：`open_dreamer`、`opendreamer`、`dreamer-4`、`dreamer4`。

推荐评测：[WorldModelBench](/zh/docs/evaluation/benchmark-hub/worldmodelbench)（动作条件世界滚动生成质量）。

## 运行时契约

输入 `prompt`、`input-path`（不传时使用内置示例）；参数 `steps`、`seed`、`plan-only`、`timeout-seconds`、`context-frames`、`horizon` 等 9 项；产物 `generated_world`、`generated_video`、`open-dreamer.mp4`。

CLI task profile：`default`。绑定的 pipeline 类是 `OpenDreamerPipeline`。

系列状态：**Runner 一致性待确认**。

`default` 的默认值：seed=0。

请就位官方检出（位于 WORLDFOUNDRY_MODEL_SOURCE_DIR/open-dreamer-inference 或 $WORLDFOUNDRY_OPEN_DREAMER_SOURCE），并带其自身的 CUDA-12 JAX 环境。上游未发布权重——需自行训练 Orbax checkpoint 或传入 checkpoint_path。上下文片段须为 RGB 368x640（或 360x640，自动零填充）。

## 在 WorldFoundry 中运行

运行 `wf run open-dreamer --pipeline.task-profile default` 推演世界模型。

运行环境：独立环境 `open-dreamer`（Python 3.11，CUDA 12.8）。

该模型没有登记公开 checkpoint；按使用说明就位权重。准备环境并检查本地资产：`bash scripts/inference/prepare_model_infer.sh open-dreamer`；下载缺失的公开权重时加 `--download`。
