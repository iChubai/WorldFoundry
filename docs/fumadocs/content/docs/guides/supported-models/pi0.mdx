π0 (pi0) is Physical Intelligence's flow-matching Vision-Language-Action model: a **PaliGemma** vision-language backbone plus a smaller **action expert** that emits continuous action chunks. The paper is [π0: A Vision-Language-Action Flow Model for General Robot Control](https://arxiv.org/abs/2410.24164). WorldFoundry runs the concrete π0 algorithm on the OpenPI runtime — this is not a LeRobot zoo policy.

<ModelPaperFigures modelId="pi0" locale="en" />

The design is built for dexterous, high-rate control. Flow matching lets the action expert represent complex continuous distributions. At run time the paper describes **action chunking** at up to **50 Hz**, with a horizon on the order of **H = 50** steps. The VLM stays responsible for images and language; the expert sees proprioception and noisy actions. Checkpoints are **not on Hugging Face**: they live at `gs://openpi-assets` and must be staged with gsutil / gcloud.

## What it is for

Roll out the π0 algorithm: `image`, `instruction`, and `prompt` in; `pi0_action_trace.json` out through `OpenPIPipeline`. Optional: `video`. The `actions` field covers `robot_action`, `proprio`, and `action_space`. Alias `openpi-pi0` resolves here. The default config is `pi0_droid`; its Orbax checkpoint must already be local.

LIBERO results for the OpenPI family come from the **pi05_libero** config, not from π0.

## Runtime contract

One checkpoint covers single-arm, bimanual, and mobile manipulators by decoding continuous controls through the action expert (PaliGemma typically tokenizes **224×224** images). For discrete FAST action tokenization, use [pi0-FAST](/docs/guides/supported-models/pi0-fast).

## Running in WorldFoundry

Stage the GCS checkpoints, then launch `wf run pi0` in the dedicated environment `worldfoundry-openpi-cu12` (Python 3.11, CUDA 12.4 or newer, JAX CUDA 12). No end-to-end GPU run of π0 has been validated yet.
