π0（pi0）是 Physical Intelligence 的 flow-matching 视觉-语言-动作模型：采用 **PaliGemma** 视觉-语言骨干和更小的 **动作专家**，输出连续动作块。论文是 [π0: A Vision-Language-Action Flow Model for General Robot Control](https://arxiv.org/abs/2410.24164)。WorldFoundry 在 OpenPI 运行时上运行具体的 π0 算法——这不是 LeRobot policy-zoo 条目。

<ModelPaperFigures modelId="pi0" locale="zh" />

该模型面向灵巧、高频率控制而设计。Flow matching 让动作专家表示复杂的连续分布。论文描述的运行时 **动作分块** 频率最高为 **50 Hz**，地平线约为 **H = 50** 步。VLM 负责处理图像和语言；专家处理本体感觉和带噪动作。π0 **没有 Hugging Face checkpoint**：权重在 `gs://openpi-assets`，必须用 gsutil / gcloud 准备。

## 用来做什么

运行 π0 算法：以 `image`、`instruction`、`prompt` 为输入，经 `OpenPIPipeline` 生成 `pi0_action_trace.json`。可选：`video`。`actions` 字段包括 `robot_action`、`proprio`、`action_space`。别名 `openpi-pi0` 解析到这里。默认配置为 `pi0_droid`，对应的 Orbax checkpoint 必须已经在本地。

OpenPI 家族的 LIBERO 结果来自 **pi05_libero** 配置，而非 π0。

## 运行时契约

单个 checkpoint 通过动作专家解码连续控制，覆盖单臂、双臂和移动操作臂（PaliGemma 图像通常是 **224×224**）。如需离散 FAST 动作分词，请使用 [pi0-FAST](/zh/docs/guides/supported-models/pi0-fast)。

## 在 WorldFoundry 中运行

准备好 GCS checkpoint 后，在独立环境 `worldfoundry-openpi-cu12`（Python 3.11，CUDA 12.4 或更新，JAX CUDA 12）里运行 `wf run pi0`。π0 尚未验证端到端 GPU 运行。
