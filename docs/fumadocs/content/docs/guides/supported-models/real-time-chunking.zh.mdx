Real-Time Chunking（RTC）不是模型，而是 Physical Intelligence 的推理期算法：让基于 flow 的 VLA 策略异步重规划动作块，使控制在实时约束下保持平滑。WorldFoundry 通过树内动作运行时适配器路由 RTC——块上下文处理无需 checkpoint。

## 用来做什么

用 `real-time-chunking` 做本卡的视觉-语言-动作推理。这条配方用来启动已记录的策略 profile。

RTC 将块切换视为 inpainting 问题：约束下一块的开头与正在执行的动作一致，消除块边界的停顿与不连续。参考实现面向 Kinetix 环境套件。

catalog 记录的任务包括 动作分块、实时控制、vla.inference_runtime。别名包括 `rtc`、`action-chunking-rtc`。

记录的评测入口包括[Kinetix](/zh/docs/evaluation/benchmark-hub/kinetix)（官方参考实现面向 Kinetix）。

## 运行时契约

必填 `state`；可选 `model_id` (real-time-chunking)、`prompt`、`image`、`policy_family`、`action_representation`；产物 `action_trace`、`real-time-chunking_action_trace.json`。

记录的任务 profile：`action_chunking`、`real_time_control`、`vla.inference_runtime`。绑定的 pipeline 类是 `RealTimeChunkingPipeline`。

系列状态：**Runner 一致性待确认**。

将 RTC 作为运行时行为叠加在 flow VLA 策略（如 pi0 家族）之上，而非作为独立策略加载。

纯算法条目：需要宿主策略配合使用。

## 在 WorldFoundry 中运行

启动 `worldfoundry-eval run real-time-chunking --pipeline.task-profile action_chunking` 执行策略。上方命令构建器按已记录任务切换 `--pipeline.task-profile`，发出的仍是 `worldfoundry-eval run`。

运行环境是统一 profile `worldfoundry-unified-cu128`（Python 3.11，CUDA 12.8）。

本卡片未记录公开 checkpoint id；按使用说明就位权重。就位权重用 `bash scripts/inference/prepare_model_infer.sh real-time-chunking`。
