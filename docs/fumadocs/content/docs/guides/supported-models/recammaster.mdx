## What it is for

`recammaster` conditions video generation on camera poses.

Per the paper (arXiv 2503.11647), ReCamMaster conditions a pre-trained text-to-video model (Wan-family in the open release) on the source video through frame-dimension conditioning, letting camera trajectories be swapped at generation time. It is published by Kuaishou (Kling Team).

Tasks: camera-controlled video rerendering. Aliases: `Camera-Controlled Generative Rendering from A Single Video`.

Suggested benchmarks: [CameraBench](/docs/evaluation/benchmark-hub/camerabench) (Directly evaluates camera-trajectory control quality).

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted); options `frames`, `fps`, `steps`, `guidance-scale`, and `camera-trajectory`; artifacts `generated_video`, `generated_4d_scene`, and `recammaster.mp4`.

CLI task profiles: `default`. WorldFoundry binds `ReCamMasterPipeline`.

Family status: **Verified**.

Defaults for `default`: frames=81, fps=8.

Stage Wan2.1 (Wan-AI/Wan2.1-T2V-1.3B) and the ReCamMaster checkpoint (KlingTeam/ReCamMaster-Wan2.1) before submitting jobs; the runtime also needs torchvision and a CUDA GPU.

## Running in WorldFoundry

Generate a camera-controlled clip with `wf run recammaster --pipeline.task-profile default`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Weights: `KlingTeam/ReCamMaster-Wan2.1` and `Wan-AI/Wan2.1-T2V-1.3B`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh recammaster`. Add `--download` to fetch missing public checkpoints.
