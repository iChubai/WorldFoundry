RoboFlamingo turns OpenFlamingo into a language-conditioned robot policy: the VLM encodes a camera frame with a task instruction, and a recurrent head emits continuous controls (typically **7-DoF** pose plus gripper). The official paper is [Vision-Language Foundation Models as Effective Robot Imitators](https://arxiv.org/abs/2311.01378) (arXiv 2311.01378). The project page is [roboflamingo.github.io](https://roboflamingo.github.io/). The GitHub tree is [RoboFlamingo/RoboFlamingo](https://github.com/RoboFlamingo/RoboFlamingo).

Validated on GPU: with three staged stacks — the released CALVIN policy, the OpenFlamingo VLM, and the MPT language backbone — the public pipeline produces a CUDA `action_trace`. Evaluate it on embodied action benchmarks, not video-generation scorecards. The alias `robo-flamingo` selects the same model.

## What it is for

Language-conditioned manipulation on a [CALVIN](/docs/evaluation/benchmark-hub/calvin)-style long-horizon suite is the intended route. Required inputs are `image`, `instruction`, `prompt`, and `video`. `RoboFlamingoPipeline` writes `roboflamingo_action_trace.json`.

Use it when you need a GPU-ready OpenFlamingo policy with explicit backbone staging. Its action head is recurrent, not a chunking or diffusion head.

## Runtime contract

Architecture defaults:

- Vision: **ViT-L-14** (OpenCLIP), language: **MPT-1B** (`mpt_dolly_3b` in config)
- **`window_size` 12**, **`n_obs_steps` 2**, fusion `post`
- Policy head: **LSTM** (`decoder_type` / `head_type` both `lstm`)
- Gripper camera on, proprioception off (`use_state=false`), **fp32**

Checkpoint directories — all must already exist under `${WORLDFOUNDRY_HFD_ROOT}`:

- `robovlms/RoboFlamingo` → `robovlms--RoboFlamingo` (released CALVIN policy)
- `openflamingo/OpenFlamingo-3B-vitl-mpt1b-langinstruct` → `openflamingo--OpenFlamingo-3B-vitl-mpt1b-langinstruct`
- `anas-awadalla/mpt-1b-redpajama-200b-dolly` → `anas-awadalla--mpt-1b-redpajama-200b-dolly`

The vision encoder file is expected at `${WORLDFOUNDRY_CKPT_DIR}/open_clip/ViT-L-14.pt`. Full official CALVIN evaluation also needs the CALVIN assets.

## Running in WorldFoundry

The environment profile is `worldfoundry-unified-cu128`; its environment YAML pins **Python 3.8** to match RoboFlamingo's upstream requirements. After staging the three checkpoints:

```
wf run roboflamingo
```
