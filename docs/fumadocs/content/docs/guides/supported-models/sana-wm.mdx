SANA-WM is a world model built on NVIDIA's efficient Sana architecture: a two-stage design (interactive stage plus LTX-2 refiner) that generates camera-controlled world video with a resident multi-GPU pipeline. Validated on four A100 GPUs: a short run generates eight decodable 1280x704 frames from a nine-frame native window.

## What it is for

`sana-wm-streaming` conditions video generation on camera poses.

Camera actions follow the official SANA-WM controls: `w/s` move forward/back, `a/d` yaw left/right, `j/l` strafe left/right, and `i/k` pitch up/down. Held actions use the official default speeds of 0.025 units and 0.6° per frame, with a gradual stop after release. Pass one action for each transition after the initial image, or provide explicit `camera_to_world` poses.

SANA-WM reuses WorldFoundry's shared Sana network, encoder, autoencoder, scheduler, and recipe components (paper arXiv 2605.15178, apache-2.0). The interactive pipeline keeps its two-stage model resident and advances with native 8k+1 temporal windows; the quality profile keeps the bidirectional stage and LTX-2 refiner enabled.

Tasks: world model, camera-controlled video, and controllable world generation. Aliases: `sana world model`, `sana-wm-2.6b`, `sana-wm-streaming`, and `Efficient-Large-Model/SANA-WM_streaming`.

Suggested benchmarks: [SANA-WM 80-Scene Benchmark](/docs/evaluation/benchmark-hub/sana-wm-bench) (The dedicated SANA-WM 80-scene benchmark), [CameraBench](/docs/evaluation/benchmark-hub/camerabench) (Camera-control adherence of world rollouts).

SANA-WM is a separate model from [SANA](/docs/guides/supported-models/sana). Score on [SANA-WM 80-Scene Benchmark](/docs/evaluation/benchmark-hub/sana-wm-bench) and [CameraBench](/docs/evaluation/benchmark-hub/camerabench).

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted); options `fps`, `guidance-scale`, `seed`, `window-frames`, and `step`; artifacts `sana-wm-streaming.mp4`.

CLI task profiles: `interactive-video`. WorldFoundry binds `SanaWMPipeline`.

Family status: **Runner parity pending**.

Component placement across GPUs is configurable. The default quality recipe uses 60 steps.

## Running in WorldFoundry

Generate a camera-controlled clip with `wf run sana-wm-streaming --pipeline.task-profile interactive-video`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Weights: `Efficient-Large-Model/SANA-WM_streaming` and `Efficient-Large-Model/SANA-WM_bidirectional`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh sana-wm-streaming`. Add `--download` to fetch missing public checkpoints.
