## Architecture

Sana's efficiency comes from a deep-compression autoencoder (32x) plus linear-attention DiT blocks and a small LLM text encoder, per the publication (arXiv 2410.10629). The recorded streaming routes use the vendored official BF16 CLI, hybrid DiT blocks, fused GDN kernels, and a causal LTX-2 VAE wrapper, synchronized from the pinned NVlabs/Sana commit; the paper's MPQ deployment path is not part of the public BF16 recipe.

## Usage notes

Integration status is runtime_ported with runner parity pending, but note the recorded evidence: the long-streaming checkpoint completed a real A100 run with 81 decoded 1280x704 frames at 16 FPS (artifact SHA256 recorded in the profile). SANA-Streaming accepts a source video path or hf:// URI. Full 50-step / longer-frame official quality parity remains pending.
