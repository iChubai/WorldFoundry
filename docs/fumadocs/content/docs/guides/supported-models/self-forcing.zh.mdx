Self-Forcing 弥合了自回归视频扩散的训练-推理差距：在训练时模拟推理过程——让每帧以自己先前生成的帧为条件——从而在单卡上实现实时流式文生视频（arXiv 2506.08009）。WorldFoundry 以原生扩散 recipe 提供离线生成与实时流式，结果与官方推理脚本逐位一致。

## 用来做什么

需要本系列的文生视频时选 `self-forcing`：prompt 进、生成视频出。它是 catalog 上的 T2V 起步线，不是编辑器，也不是世界模型步进器。

因果 Wan2.1 T2V 1.3B generator（gdhe17/Self-Forcing 的 self_forcing_dmd.pt）在 shift 5 的 flow 时间表上，以 1000、750、500、250 四个蒸馏 x0 步去噪每个三潜帧块，再在时间步 0 把干净的块写入 21 个潜帧的 KV 缓存。rollout 由 autoregressive-window runner 负责；Wan2.1 umT5 编码器提供条件，bf16 的 Wan2.1 VAE 整段或逐块解码。该模型由Adobe 研究院 / 得克萨斯大学奥斯汀分校发布。

catalog 记录的任务包括 文生视频、autoregressive-video-generation。别名包括 `Self-Forcing`、`selfforcing`、`self_forcing`。模态上，它接受文本，输出视频。

记录的评测入口包括[VBench](/zh/docs/evaluation/benchmark-hub/vbench)（流式文生视频的质量评测）。

## 运行时契约

可选 `prompt`、`frames`、`fps`、`height`、`width`；产物 `self-forcing.mp4`。

CLI task profile：`interactive-video`。绑定的 pipeline 类是 `NativeSelfForcingPipeline`。

系列状态：**已验证**。

`interactive-video` 记录默认值：frames=81, fps=16, height=480, width=832, seed=0。

默认值沿用官方 CLI：480x832、81 帧（21 个潜帧）、四步、guidance 1.0、16 fps；num_frames 须对应 3 的倍数个潜帧，最多 21 个。 实时会话首块输出 9 帧、之后每块 12 帧，81 帧共 7 块。 加载时传入 kv_window="sink5-window7-rerope" 会启用近似长滚动缓存，用于更长的视频和无界流式生成。
