## What it is for

Pick `spatial-forcing-libero-spatial` when you want the catalog VLA policy: instruction and observation in, an action trace out. Use it to roll the recorded policy, not to train a new one.

Fine-tuned OpenVLA 7B checkpoints where spatial alignment was enforced during training; at inference the models run as standard OpenVLA-style policies. The inference-only runtime disables checkpoint-hosted remote code; VGGT, alignment projectors, and LoRA adapter copies are excluded.

Catalog tasks include vla, vla action prediction, and vla policy rollout. Catalog aliases include `spatial_forcing` and `spatial-forcing-openvla`. Also recorded: `spatial-forcing-libero-object`, `spatial-forcing-libero-goal`, `spatial-forcing-libero-10`.

Recorded evaluation entry points include [LIBERO](/docs/evaluation/benchmark-hub/libero) (All four LIBERO checkpoints are GPU-validated).

## Running in WorldFoundry

The catalog launch is `worldfoundry-eval run spatial-forcing-libero-spatial --pipeline.task-profile vla.policy_rollout`. The command builder above switches `--pipeline.task-profile` among recorded tasks and still emits `worldfoundry-eval run`.

It runs in the dedicated environment `worldfoundry-vla-spatial-forcing-cu121` (Python 3.10, CUDA 12.1, torch==2.2.0).

Recorded weight repositories include `haofuly/spatial-forcing-7b-finetuned-libero-spatial`, `haofuly/spatial-forcing-7b-finetuned-libero-object`, and `haofuly/spatial-forcing-7b-finetuned-libero-goal` among others. Stage assets with `bash scripts/inference/prepare_model_infer.sh spatial-forcing-libero-spatial`.
