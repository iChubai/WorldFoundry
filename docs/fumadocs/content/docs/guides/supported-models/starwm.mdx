StarWM is a multi-agent world model for StarCraft-style environments: it predicts action-conditioned game video across many interacting units. WorldFoundry includes the official offline inference client; jobs talk to an OpenAI-compatible StarWM endpoint using the official prompt fixture format. The checkpoint is yxzhang2024/StarWM on Hugging Face.

## What it is for

Use `starwm` to step a world forward with actions and render the resulting frames.

The runtime is an endpoint-client design: the route builds the official run_inference_client.py command and validates input_file, mode, and served_model_id/api_model_id before execution.

Tasks: multi agent world model, starcraft world model, and action-conditioned video.

Suggested benchmarks: [WorldModelBench](/docs/evaluation/benchmark-hub/worldmodelbench) (Action-conditioned game-world rollout quality).

## Runtime contract

Inputs `load.input-file` and `load.served-model-id` (bundled samples are used when omitted); options `plan-only` and `timeout-seconds`; artifacts `generated_world` and `starwm_predictions.jsonl`.

CLI task profiles: `starcraft-offline-client`. WorldFoundry binds `StarWMPipeline`.

Family status: **Runner parity pending**.

Actual generation requires a running OpenAI-compatible StarWM endpoint; the WorldFoundry route only builds and validates the client command.

Needs an externally served StarWM endpoint; it cannot run standalone.

## Running in WorldFoundry

Step the world with `wf run starwm --pipeline.task-profile starcraft-offline-client`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Weights: `yxzhang2024/StarWM`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh starwm`. Add `--download` to fetch missing public checkpoints.
