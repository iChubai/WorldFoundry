TinyVLA targets fast, data-efficient VLA at sub-billion scale: LLaVA-Pythia backbones (400M / 700M / 1.3B released on the Hub) with ACT or conditional 1D-diffusion action heads. The published Hub models are VLM backbones for policy training — not task-trained robot checkpoints — so you need to stage your own trained task policy to run it.

## What it is for

Use `tinyvla` to predict robot actions from observations and a language instruction.

LLaVA-Pythia multimodal backbones with CLIP/SigLIP vision fusion and swappable action heads (ACT or conditional 1D diffusion), executed fully in process. Both merged weights and local LoRA plus non-LoRA action tensors are supported.

Tasks: VLA, VLA action prediction, and embodied policy. Aliases: `tiny-vla` and `llava-pythia-vla`.

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted); artifacts `action_trace` and `tinyvla_action_trace.json`.

CLI task profiles: `default`. WorldFoundry binds `TinyVLAPipeline`.

Family status: **Runner parity pending**.

Stage a compatible task checkpoint, its config.json (action dimensions and head type), and dataset statistics locally; the runtime does not start without them.

No public task-trained action checkpoint; released Hub models are backbones only.

## Running in WorldFoundry

Run `wf run tinyvla --pipeline.task-profile default` to predict actions.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8, torch>=2.5).

Weights: `lesjie/Llava-Pythia-400M`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh tinyvla`. Add `--download` to fetch missing public checkpoints.
