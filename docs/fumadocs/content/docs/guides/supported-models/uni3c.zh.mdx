阿里巴巴达摩院的 Uni3C 将相机控制与人体动作控制统一到图生视频中：PCDController 阶段负责相机操控，统一阶段结合相机与人体动作（RealisDance-DiT）。WorldFoundry 运行两条官方第二阶段推理路径，使用公开的 Apache-2.0 checkpoint（ewrfcas/Uni3C、theFoxofSky/RealisDance-DiT），构建在 Wan2.1-I2V-14B-720P 基座之上。

## 用来做什么

`uni3c` 以相机位姿为条件生成视频。

使用三个 checkpoint：ewrfcas/Uni3C 为 PCDController，Wan-AI/Wan2.1-I2V-14B-720P-Diffusers 为相机基座，theFoxofSky/RealisDance-DiT 为相机+人体统一模型。预渲染控制包作为显式运行时输入。

任务：图生视频、相机可控视频、human-motion-controlled-video。别名：`PCDController`、`alibaba-damo-academy/Uni3C`。模态上，它接受图像，输出视频。

推荐评测：[CameraBench](/zh/docs/evaluation/benchmark-hub/camerabench)（显式控制下的相机轨迹跟随）。

## 运行时契约

输入 `prompt`、`input-path`、`render-path`（不传时使用内置示例）；参数 `mode`、`num-frames`、`fps`、`max-area`、`seed`、`num-gpus`；产物 `generated_video`、`uni3c.mp4`。

CLI task profile：`image-camera-control-video`。绑定的 pipeline 类是 `Uni3CPipeline`。

系列状态：**已验证**。

`image-camera-control-video` 的默认值：fps=16, seed=0。

按需选择仅相机或相机+人体统一路线，并提供匹配的预渲染控制包。已在 H100 上用官方 checkpoint 验证：默认 PCDController 相机路线可端到端运行。

独立 `uni3c` 环境中须安装 WorldFoundry。仅相机与统一推理均通过包模块运行，多 GPU 请求使用 torchrun。序列并行、相机模式的 FSDP 与统一模式的顺序 CPU offload 保留原有控制选项；运行时不向导入路径添加源码目录。

## 在 WorldFoundry 中运行

用 `wf run uni3c --pipeline.task-profile image-camera-control-video` 生成相机可控视频。

运行环境：独立环境 `uni3c`（Python 3.10，CUDA 12.4，torch==2.6.0+cu124）。

权重仓库：`ewrfcas/Uni3C`、`Wan-AI/Wan2.1-I2V-14B-720P-Diffusers`、`theFoxofSky/RealisDance-DiT`。准备环境并检查本地资产：`bash scripts/inference/prepare_model_infer.sh uni3c`；下载缺失的公开权重时加 `--download`。
