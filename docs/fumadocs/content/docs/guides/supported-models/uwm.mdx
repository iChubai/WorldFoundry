## What it is for

`uwm` is an action-conditioned world model: actions and a starting frame in, a rollout out.

UWM is a video-action diffusion design: one diffusion process jointly models future observations and robot actions, so the same network serves prediction and policy roles. It is published by University of Washington (WEIRD Lab).

Tasks: robot world model, action-conditioned video, and video action diffusion. Aliases: `uwm-libero90` and `uwm-droid`.

Suggested benchmarks: [LIBERO](/docs/evaluation/benchmark-hub/libero) (The uwm-libero90 variant targets LIBERO tasks), [EWMBench](/docs/evaluation/benchmark-hub/ewmbench) (Robot world-model rollout quality).

## Runtime contract

Artifacts `generated_video` and `uwm_runtime_plan.json`.

CLI task profiles: `default`. WorldFoundry binds `UWMPipeline`.

Family status: **Runner parity pending**.

Pick the LIBERO-90 or DROID variant to match your evaluation suite. Until the required checkpoints and assets are staged, a run outputs a runtime plan that lists the missing assets instead of generating.

Checkpoints and datasets are not bundled and must be staged before running.

## Running in WorldFoundry

Run `wf run uwm --pipeline.task-profile default` to roll out the world model.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

No public checkpoint is listed for this model; stage the weights as described in the usage notes. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh uwm`. Add `--download` to fetch missing public checkpoints.
