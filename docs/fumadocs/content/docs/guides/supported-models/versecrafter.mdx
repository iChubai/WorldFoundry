VerseCrafter from Tencent ARC is a camera-controlled image-to-video world model built on 4D control: a geometry-aware rendering stage produces 4D control signals that guide the diffusion stage along the requested camera path. It runs with the TencentARC/VerseCrafter checkpoint plus Wan-AI/Wan2.1-T2V-14B and Ruicheng/moge-2-vitl-normal.

## What it is for

`versecrafter` conditions video generation on camera poses.

Two stages: camera-only 4D-control rendering, followed by a diffusion stage whose backbone comes from VideoX-Fun. It is published by Tencent ARC Lab.

Tasks: camera-controlled video, image-to-video, and world model. Modalities: image in, video out.

Suggested benchmarks: [CameraBench](/docs/evaluation/benchmark-hub/camerabench) (Camera-path adherence for 4D-controlled generation).

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted); options `frames`, `fps`, `height`, `width`, `steps`, `guidance-scale`, and 1 more; artifacts `versecrafter.mp4`.

CLI task profiles: `default`. WorldFoundry binds `VerseCrafterPipeline`.

Family status: **Verified**.

Defaults for `default`: frames=81, fps=16, height=480, width=832, seed=2025.

Validated with the released checkpoint: a short camera-controlled video generates end to end, with visible artifacts in late frames.

## Running in WorldFoundry

Generate a camera-controlled clip with `wf run versecrafter --pipeline.task-profile default`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Weights: `TencentARC/VerseCrafter`, `Wan-AI/Wan2.1-T2V-14B`, and `Ruicheng/moge-2-vitl-normal`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh versecrafter`. Add `--download` to fetch missing public checkpoints.
