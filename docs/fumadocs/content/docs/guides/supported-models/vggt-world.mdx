VGGT-World builds a world model on top of VGGT-style 3D scene understanding: it couples geometry-grounded scene perception with video generation so rollouts stay consistent with the underlying 3D structure. WorldFoundry binds the official source (paper: arXiv 2603.12655); generation needs the checkpoints and assets staged locally.

## What it is for

`vggt-world` is a world generation model.

Per the paper (arXiv 2603.12655), VGGT is turned into an autoregressive geometry world model.

Tasks: world model, 3D scene understanding, and video generation. Output modalities: video.

Suggested benchmarks: [WorldScore](/docs/evaluation/benchmark-hub/worldscore) (Unified world-generation quality across 3D-grounded rollouts).

This is not [VGGT](/docs/guides/supported-models/vggt) or [VGGT-Omega](/docs/guides/supported-models/vggt-omega).

## Runtime contract

Artifacts `generated_world` and `vggt_world_runtime_plan.json`.

CLI task profiles: `default`. WorldFoundry binds `VGGTWorldPipeline`.

Family status: **Runner parity pending**.

Stage the required checkpoints and assets first. Until they are in place, a run writes `vggt_world_runtime_plan.json` listing the missing assets instead of generating a world.

The upstream repository has no root license: legal review is required before use.

## Running in WorldFoundry

Run `wf run vggt-world --pipeline.task-profile default` to generate the world.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

No public checkpoint is listed for this model; stage the weights as described in the usage notes. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh vggt-world`. Add `--download` to fetch missing public checkpoints.
