## 用来做什么

用 `wall-oss` 做本卡的视觉-语言-动作推理。这条配方用来启动已记录的策略 profile。

同一基础策略的两种解码变体：flow-matching 头（wall-oss-flow）与 FAST 离散 token 头（wall-oss-fast）。官方仓库指针之外的架构内部细节仓库未记录。

catalog 记录的任务包括 VLA 动作预测、VLA 策略执行。别名包括 `wall_oss`、`x-square-robot/wall-oss-flow`。

## 运行时契约

必填 `image`、`prompt`、`state`；可选 `model_id` (wall-oss)、`policy_family`、`action_representation`；产物 `action_trace`、`wall-oss_action_trace.json`。

记录的任务 profile：`vla.action_prediction`、`vla.policy_rollout`。绑定的 pipeline 类是 `WallOSSPipeline`。

系列状态：**Runner 一致性待确认**。

checkpoint 缺失由运行时 missing_assets 报告，不视为 catalog 阻塞；权重就位前运行输出运行时计划。 平滑连续控制选 flow，低延迟解码选 fast。

checkpoint 驱动 parity 尚未验证。

## 在 WorldFoundry 中运行

启动 `worldfoundry-eval run wall-oss --pipeline.task-profile vla.action_prediction` 执行策略。上方命令构建器按已记录任务切换 `--pipeline.task-profile`，发出的仍是 `worldfoundry-eval run`。

运行环境是统一 profile `worldfoundry-unified-cu128`（Python 3.11，CUDA 12.8）。

记录的权重仓库包括 `x-square-robot/wall-oss-flow`、`x-square-robot/wall-oss-fast`。就位权重用 `bash scripts/inference/prepare_model_infer.sh wall-oss`。

状态：**Runner 一致性待确认**。
