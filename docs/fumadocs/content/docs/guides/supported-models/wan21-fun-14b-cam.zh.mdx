Wan2.1-Fun V1.1 14B Control Camera 是阿里云 PAI 在 VideoX-Fun 家族中 Wan2.1 世代最大的相机控制 checkpoint：由显式相机位姿序列操控的图生视频。WorldFoundry 内置 VideoX-Fun（revision 403f1f7b），运行 alibaba-pai/Wan2.1-Fun-V1.1-14B-Control-Camera checkpoint；该 checkpoint 采用 Apache-2.0 许可。

## 用来做什么

视角需要沿指定相机路径运动时，用 `wan21-fun-14b-cam`。

14B 参数的 Wan2.1 扩散 Transformer，叠加 VideoX-Fun Control-Camera 条件通路：相机外参作为控制信号与图像条件一同注入。该模型由阿里云 PAI（VideoX-Fun）发布。

任务：相机可控视频、图生视频。模态上，它接受图像，输出视频。

推荐评测：[CameraBench](/zh/docs/evaluation/benchmark-hub/camerabench)（受控图生视频的相机位姿跟随）。

基座模型见 [Wan2.1](/zh/docs/guides/supported-models/wan2.1)；更小的相机控制 checkpoint 见 [Wan2.1 Fun 1.3B Cam](/zh/docs/guides/supported-models/wan21-fun-1p3b-cam)。评测看 [CameraBench](/zh/docs/evaluation/benchmark-hub/camerabench)。

## 运行时契约

输入 `prompt`、`input-path`（不传时使用内置示例）；参数 `frames`、`fps`、`height`、`width`、`steps`、`seed` 等 7 项；产物 `wan21-fun-14b-cam.mp4`。

CLI task profile：`default`。绑定的 pipeline 类是 `Wan21Fun14BCameraPipeline`。

系列状态：**Runner 一致性待确认**。

相机位姿序列需显式提供。同路由的 1.3B 版本（wan21-fun-1p3b-cam）已通过 GPU 验证，可作参照。

14B 规模意味着显存需求远高于 1.3B 变体。

## 在 WorldFoundry 中运行

运行 `wf run wan21-fun-14b-cam --pipeline.task-profile default` 沿相机路径生成视频。

运行环境：统一环境 `worldfoundry-unified-cu128`（Python 3.11，CUDA 12.8）。

权重仓库：`alibaba-pai/Wan2.1-Fun-V1.1-14B-Control-Camera`。准备环境并检查本地资产：`bash scripts/inference/prepare_model_infer.sh wan21-fun-14b-cam`；下载缺失的公开权重时加 `--download`。
