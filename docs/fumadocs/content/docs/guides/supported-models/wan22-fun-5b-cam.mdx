## What it is for

`wan22-fun-5b-cam` conditions video generation on camera poses.

A 5B-parameter Wan2.2 diffusion transformer with the VideoX-Fun Control-Camera conditioning pathway. It is published by Alibaba PAI (VideoX-Fun).

Tasks: camera-controlled video and image-to-video. Modalities: image in, video out.

Suggested benchmarks: [CameraBench](/docs/evaluation/benchmark-hub/camerabench) (Camera-pose adherence for controlled i2v generation), [WRBench](/docs/evaluation/benchmark-hub/wrbench) (Native 121-frame/24FPS profile suits WRBench-style requests).

For base Wan2.2 generation or the A14B camera-control model, use [Wan2.2](/docs/guides/supported-models/wan2.2) or [Wan2.2 Fun A14B Cam](/docs/guides/supported-models/wan22-fun-a14b-cam).

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted); options `frames`, `fps`, `height`, `width`, `steps`, `seed`, and 1 more; artifacts `wan22-fun-5b-cam.mp4`.

CLI task profiles: `default`. WorldFoundry binds `Wan22Fun5BCameraPipeline`.

Family status: **Runner parity pending**.

The upstream native profile is 121 frames at 24 FPS; WRBench requests pass explicit values, so set frame count and FPS deliberately rather than relying on defaults.

## Running in WorldFoundry

Generate a camera-controlled clip with `wf run wan22-fun-5b-cam --pipeline.task-profile default`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Weights: `alibaba-pai/Wan2.2-Fun-5B-Control-Camera`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh wan22-fun-5b-cam`. Add `--download` to fetch missing public checkpoints.
