Wan2.2-Fun A14B Control Camera is the largest Wan2.2-generation camera-control checkpoint in the VideoX-Fun family: an A14B (mixture-of-experts style) diffusion backbone steered by explicit camera pose sequences for image-to-video. It uses the alibaba-pai/Wan2.2-Fun-A14B-Control-Camera checkpoint (Apache-2.0).

## What it is for

`wan22-fun-a14b-cam` generates camera-controlled video: a camera trajectory in, a clip that follows it out.

An A14B Wan2.2 diffusion backbone with the VideoX-Fun Control-Camera conditioning pathway. It is published by Alibaba PAI (VideoX-Fun).

Tasks: camera-controlled video and image-to-video. Modalities: image in, video out.

Suggested benchmarks: [CameraBench](/docs/evaluation/benchmark-hub/camerabench) (Camera-pose adherence for controlled i2v generation).

Related models: [Wan2.2](/docs/guides/supported-models/wan2.2) and [Wan2.2 Fun 5B Cam](/docs/guides/supported-models/wan22-fun-5b-cam).

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted); options `frames`, `fps`, `height`, `width`, `steps`, `seed`, and 1 more; artifacts `wan22-fun-a14b-cam.mp4`.

CLI task profiles: `default`. WorldFoundry binds `Wan22FunA14BCameraPipeline`.

Family status: **Runner parity pending**.

Reserve this variant for maximum-quality camera-controlled generation once your pipeline is proven on the GPU-validated 1.3B sibling; A14B checkpoints demand the largest VRAM budget in the family.

## Running in WorldFoundry

Run `wf run wan22-fun-a14b-cam --pipeline.task-profile default` to follow the camera path.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Weights: `alibaba-pai/Wan2.2-Fun-A14B-Control-Camera`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh wan22-fun-a14b-cam`. Add `--download` to fetch missing public checkpoints.
