## What it is for

Use `wonderjourney` to generate an explorable world.

Per the paper (arXiv 2312.03884), an LLM proposes upcoming scene descriptions, a point-cloud-and-inpainting visual module renders each new scene from the previous one, and a VLM verifies results. It is published by Stanford University / Google.

Tasks: 3D world generation, scene expansion, and image-to-3D-world. Modalities: image in, 3D scene and world state out.

Suggested benchmarks: [WorldScore](/docs/evaluation/benchmark-hub/worldscore) (Standard scoring for generated navigable scene sequences).

## Runtime contract

Inputs `prompt` (bundled samples are used when omitted); options `config` and `python-executable`; artifacts `generated_world` and `wonderjourney.mp4`.

CLI task profiles: `default`. WorldFoundry binds `WonderJourneyPipeline`.

Family status: **Runner parity pending**.

Stage the upstream assets (depth, inpainting, LLM access) locally before generating journeys; without them a run produces only a plan.

Scene-to-scene generation accumulates style and geometry drift over long journeys.

## Running in WorldFoundry

Run `wf run wonderjourney --pipeline.task-profile default` to generate the world.

It runs in the dedicated environment `wonderworld` (Python 3.10, CUDA 12.4).

No public checkpoint is listed for this model; stage the weights as described in the usage notes. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh wonderjourney`. Add `--download` to fetch missing public checkpoints.
