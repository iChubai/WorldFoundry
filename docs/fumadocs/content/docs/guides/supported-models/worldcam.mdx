## What it is for

`worldcam` conditions video generation on camera poses.

The runner follows the official conditioning-video path and consumes WorldCam and Wan assets, indicating a Wan-based diffusion backbone with camera-pose conditioning. It is published by KAIST / Adobe Research / MAUM AI.

Tasks: world, camera control, and world model.

Suggested benchmarks: [CameraBench](/docs/evaluation/benchmark-hub/camerabench) (Camera-pose-controlled rollout adherence), [WorldModelBench](/docs/evaluation/benchmark-hub/worldmodelbench) (Long-horizon interactive world quality).

## Runtime contract

Required `input-path`; inputs `prompt` (bundled samples are used when omitted); options `fps`, `height`, `width`, `steps`, `guidance-scale`, `seed`, and 7 more; artifacts `worldcam.mp4`.

CLI task profiles: `interactive-video`. WorldFoundry binds `WorldCamPipeline`.

Family status: **Verified**.

Defaults for `interactive-video`: fps=30, height=480, width=832, seed=0.

The release is code-only, so stage the WorldCam and Wan2.1-T2V-1.3B assets locally yourself; the wrapper's load_model=False mode lets you check planning without weights.

## Running in WorldFoundry

Run `wf run worldcam --pipeline.task-profile interactive-video` to follow the camera path.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Weights: `worldcam/worldcam` and `Wan-AI/Wan2.1-T2V-1.3B`. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh worldcam`. Add `--download` to fetch missing public checkpoints.
