## What it is for

Use `worldcam` for camera-conditioned video inference. The recipe binds the recorded camera-control profile.

The in-tree runner follows the official conditioning-video path and consumes local WorldCam/Wan assets, indicating a Wan-based diffusion backbone with camera-pose conditioning. Architecture internals beyond this are not recorded in this repository. It is published by KAIST / Adobe Research / MAUM AI.

Catalog tasks include world, camera control, and world model.

Recorded evaluation entry points include [CameraBench](/docs/evaluation/benchmark-hub/camerabench) (Camera-pose-controlled rollout adherence), [WorldModelBench](/docs/evaluation/benchmark-hub/worldmodelbench) (Long-horizon interactive world quality).

## Running in WorldFoundry

The catalog launch is `worldfoundry-eval run worldcam --pipeline.task-profile world`. The command builder above switches `--pipeline.task-profile` among recorded tasks and still emits `worldfoundry-eval run`.

It runs in the unified environment `worldfoundry-unified-cu128` (Python 3.11, CUDA 12.8).

Recorded weight repositories include `worldcam/worldcam` and `Wan-AI/Wan2.1-T2V-1.3B`. Stage assets with `bash scripts/inference/prepare_model_infer.sh worldcam`.
