World Labs API is the hosted route to World Labs' generative world service, for world generation and asset outputs rather than flat video. Instead of returning a clip, the service produces explorable 3D world content on World Labs' infrastructure; WorldFoundry saves what the API returns as artifacts.

## What it is for

Use `worldlabs` to call the hosted model through WorldFoundry.

World Labs has not published the architecture behind its world generation service.

Tasks: world generation, assets, and hosted api.

Suggested benchmarks: [WorldScore](/docs/evaluation/benchmark-hub/worldscore) (Unified benchmark for scoring generated explorable worlds).

World Labs' Marble 1.1 model has its own page: [Marble 1.1](/docs/guides/supported-models/worldlabs-marble-1.1).

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted).

CLI task profiles: `default`. WorldFoundry binds `WorldLabsPipeline`.

Supply your own World Labs account and API key through WORLDLABS_API_KEY (or WLT_API_KEY); access is provisioned through World Labs' platform (worldlabs.ai). No weights are downloaded and no local GPU is needed — generation happens on the provider side, so cost, quota, and content policy follow your provider account.

Requires a paid provider account and API key; WorldFoundry does not ship credentials.

The provider controls model versioning, so outputs can change over time.

## Running in WorldFoundry

Call the hosted model with `wf run worldlabs --pipeline.task-profile default`.

No runtime environment is recorded for this model.

Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh worldlabs`. Add `--download` to fetch missing public checkpoints.
