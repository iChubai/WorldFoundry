Xiaomi-Robotics-1 is Xiaomi's next-generation VLA (Apache-2.0): a Qwen3-VL policy-token graph with a rectified-flow DiT action decoder emitting relative actions. Checkpoints are staged locally under WORLDFOUNDRY_CKPT_DIR.

## What it is for

`xiaomi-robotics-1` maps camera observations and an instruction to an action trajectory.

A Qwen3-VL backbone produces policy tokens consumed by a rectified-flow DiT that decodes relative actions. Normalization metadata in checkpoint-side Python files is parsed as literals and never executed. It is published by Xiaomi Robotics.

Tasks: VLA, VLA action prediction, VLA policy rollout, and robot policy. Aliases: `xr1` and `xiaomi-robotics-one`.

Not [Xiaomi Robotics 0](/docs/guides/supported-models/xiaomi-robotics-0).

## Runtime contract

Inputs `prompt` and `input-path` (bundled samples are used when omitted); artifacts `action_trace` and `xiaomi_robotics_1_action_trace.json`.

CLI task profiles: `default`. WorldFoundry binds `XiaomiRobotics1Pipeline`.

Family status: **Runner parity pending**.

Stage checkpoints under $\{WORLDFOUNDRY_CKPT_DIR\}/embodied_action/xiaomi-robotics-1. The model, processor, and checkpoint load only from local files.

The public repository is a pre-release project page; the inference snapshot is not published there.

## Running in WorldFoundry

Run `wf run xiaomi-robotics-1 --pipeline.task-profile default` to predict actions.

It runs in the dedicated environment `worldfoundry-xiaomi-robotics-1-cu128` (Python 3.12, CUDA 12.8, torch==2.8.0).

No public checkpoint is listed for this model; stage the weights as described in the usage notes. Prepare the environment and check local assets with `bash scripts/inference/prepare_model_infer.sh xiaomi-robotics-1`. Add `--download` to fetch missing public checkpoints.
