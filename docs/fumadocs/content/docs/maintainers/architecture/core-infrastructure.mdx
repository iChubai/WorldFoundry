## Why this layer exists

`worldfoundry/core` is the shared inference infrastructure that every model family reuses and none of them owns. Checkpoint loading, state-dict remapping, attention backends, distributed collectives, VRAM placement and offload, kernels, configuration, media IO, memory contracts, and safety guardrails all live here once. A family package (`worldfoundry/base_models/*`, `worldfoundry/synthesis/*`, `worldfoundry/pipelines/*`) composes these primitives; it must not recreate them.

This is the layer to read when you are about to copy a utility into a model directory. The rule is explicit: if multiple families actually reuse a capability, it belongs in `core`; an adapter tied to a specific model belongs with that model. See [Native diffusion](/docs/maintainers/architecture/native-diffusion) for how diffusion consumes this layer, and [Model runtime](/docs/maintainers/architecture/model-runtime) for how pipelines and operators do.

## Dependency rule

`core` may depend on PyTorch, `diffusers` model/operator primitives, and narrow third-party libraries. It must not import `worldfoundry.pipelines`, `worldfoundry.synthesis`, `worldfoundry.operators`, `worldfoundry.base_models` family packages, or `worldfoundry.evals`, or `worldfoundry.studio`. The edge points *out of* family packages *into* `core`, never the reverse.

This keeps family packages thin: a model directory contains checkpoint-compatible tensor math and contract adapters, not a second copy of an offload manager, a distributed bootstrap, a kernel registry, or a quantization system. When you find yourself adding one of those to a family package, move it to `core` first and import it from there.

<Callout type="info">
  The diffusion package restates this rule for its own boundary in [Native diffusion](/docs/maintainers/architecture/native-diffusion). Generic attention, transformer, loading, and offload primitives live in `core`; diffusion-domain contracts, schedulers, and recipes live in `base_models/diffusion_model`.
</Callout>

### Layering inside core

Core subpackages form a fixed stack. A module imports from its own layer or lower layers, and modules in one layer never import each other in a cycle. From the bottom up:

1. `utils`, the root modules `registry`, `contracts`, `env_registry`, `prompting`, `action_normalization`, and the independent leaves `execution.deadline`, `model_loading.policy`
2. `observability`
3. `io`
4. `configuration`, `platform`
5. `distributed`
6. `media`, `geometry`, `kernels`
7. `attention`
8. `nn`
9. `model_loading/checkpoints`
10. `acceleration`, `vram`
11. `model_loading`
12. `execution`, `memory`, `safety`

A helper that a lower layer needs moves down to that layer instead of being imported upward. `tests/core/test_core_module_boundaries.py` holds the table and fails on any upward import.

## Where it is consumed

- **Diffusion** — `base_models/diffusion_model` loads checkpoints through `core/model_loading`, runs attention through `core/attention`, and offloads through `core/vram`. Its `optimizations/` re-exports core policy, not a parallel implementation.
- **Hosted and native runtimes** — `synthesis/` stages inputs through `core/io` and writes artifacts through `core/media`.
- **Memory** — `core/memory/base.py` defines the contract; streaming and long-context state in `synthesis/*/memory` and action-policy trace state in `synthesis/action_generation/memory.py` implement it.
- **Distributed execution** — `core/distributed` is the only place model-parallel groups are initialized; no family package boots its own NCCL group.

### Cache and memory identity

Local sharded safetensors caches record the index and referenced shard paths, sizes, and nanosecond modification times in the merged file's metadata. Reuse requires matching source state; changed or missing source files cannot be hidden by a merged cache. Cache publication remains atomic.

`MemoryStore` default timestamps advance independently of capacity eviction. Explicit and restored numeric timestamps advance the next default timestamp; `reset()` starts a new timeline, and `replace()` rebuilds it from the supplied records. Recency ranking uses these record timestamps rather than the bounded list length.

## What does not belong here

Training entrypoints, training-only datasets and dataloaders, losses, callbacks, augmentation-only modules, and experiment scripts do not belong in `core`, nor in `base_models`. `core` is inference infrastructure; if a module only matters during training, it should not be added here.

For the directory-level map of every package, see [Codebase map](/docs/maintainers/architecture/file-index). For how a model call flows through these primitives, see [Model runtime](/docs/maintainers/architecture/model-runtime) and [Runtime assembly](/docs/maintainers/architecture/runtime-assembly).

## Ownership decisions

- `checkpoint` is part of `model_loading/checkpoints`; weight loading, assignment and conversion have one owner.
- Media codecs and video processing helpers share `media`; downloading and filesystem work stay in `io`.
- CUDA graphs, prewarm, frame prefetch and overlap belong to `execution`; encoder placement/lifetime belongs to `vram`.
- `memory` stays separate from `vram`: context/retrieval is a model input concern, while placement/offload manages physical memory.
- Configuration helpers belong to `configuration`, terminal formatting to `observability`, and runtime scheduling to `execution`.
- `target`/`class_path` factories belong to `configuration`; rank-aware logging belongs to `observability`.
- Accelerator detection and the persistent compile cache belong to `platform`; attention projection and precision schedules belong to `acceleration`; eval-only feature helpers live in `worldfoundry/evals`.
- Wan sequence-parallel adapters and VGGT observation preprocessing live in their model families. Repository inventory audits live in `scripts/model_zoo`.

Each subpackage's lazy export table lists only that package's own modules, so `worldfoundry.core.io` exports I/O names and media helpers come from `worldfoundry.core.media`. The `worldfoundry.core` facade maps every public name to the module that defines it. Internal module imports use the owning module directly; there are no compatibility wrappers.

## Regression gates

`tests/core/test_core_module_boundaries.py` checks lazy targets and core imports without optional model dependencies. It also guards against dependencies from core into model/application packages, enforces the layer table above, and keeps every export table pointing at the owning modules. Runtime facade tests run in model environments.

Real-checkpoint changes also require `make test-geometry`: use fixed inputs, checkpoints, environments and seeds, compare numerical outputs against an accepted reference, and verify the replay hashes still match the current source. Moving files must preserve computation as well as importability.
