# Kairos Sensenova 4B 480P GPU validation

The local Kairos Sensenova 4B 480P DiT, Qwen2.5-VL-7B text encoder, and Wan VAE loaded on H100 GPU 1. The in-tree Kairos runtime accepted a real toy photograph and text prompt, completed its 50 denoising steps, decoded nine 640×480 frames, and wrote [future_world.mp4](future_world.mp4) (SHA-256 `698ff0152e3a8a5cb62c4916f23135d0d2e006fd13440727fa5e551bf136a65b`). [result.json](result.json) and [status.json](status.json) record successful output and frame checks. Runtime was about 321 seconds including model loading and a 103-second inference stage.

I viewed frames 0, 4, and 8 in [contact-0-4-8.jpg](contact-0-4-8.jpg). The turquoise toy, white plate, red table and painted wall remain recognizable, but the nine-frame output is nearly static (mean absolute pixel difference from frame 0: 2.37 at frame 4, 0.88 at frame 8). This is **verified inference only**; it does not demonstrate the prompted camera push-in, long-horizon dynamics, or robot-task success. [quality-review.json](quality-review.json) records the visual finding and temporal pixel differences.

The first attempt failed during VAE encoding because Kairos counted only its local `CausalConv3d` modules when allocating feature-cache slots. Its encoder also uses causal convolutions from shared Wan residual and resample blocks. [wan_video_vae.py](../../worldfoundry/synthesis/visual_generation/kairos/kairos_runtime/kairos/modules/vaes/wan_video_vae.py) now counts all three classes. A small encoder forward check with one frame followed by four frames stayed within the allocated slots and returned finite outputs. The full checkpoint rerun passed the earlier failure point and generated the video. [run.py](run.py) and [retry-cache.log](retry-cache.log) preserve the replay path and complete run log.
