# SCOPE GPU validation (2026-09-23)

SCOPE's in-tree pipeline loaded the local `zizhaotong--SCOPE` DiT shards, UMT5, and Wan2.2 VAE and completed two real action-conditioned inference runs on H100 GPU 0. Both output MP4s decoded at the requested frame count and resolution, with finite, nonconstant pixels. The tested action parquet has the six expected buttons and two 2D joystick fields; `j_left=[0,0.7]` requests forward motion. This is a short-path validation, not an official control benchmark.

The first real forward failed before sampling because `ScopeActionBlock.forward` rejected the base Wan model's internal `_worldfoundry_rope_precision` argument. The product fix in `scope_action.py` accepts the internal RoPE/sparse-attention keywords and forwards them to self-attention. A second run completed diffusion and VAE decoding but failed during MP4 writing because the system Python lacked the declared optional `imageio` dependency. The successful runs used `../envs/worldfoundry-unified-cu121/bin/python`, where the video extra is installed. The first and second error logs are retained as `first-failure.log` and `second-failure.log`; the successful subprocess logs and JSON results are next to the clips.

Validation: both runs used the public `SCOPEPipeline.from_pretrained(..., device='cuda:0')` and `execute=True`; `validate_outputs.py` decoded every frame, checked pixel finiteness, dimensions and frame count. The 20-step clip's first/last mean pixel delta is 33.58/255. `python3 -m py_compile` and `git diff --check` passed for the changed block. The appropriate ledger status is `quality_concern`: inference works after the fix, while observed visual artifacts remain and task-level control quality is unproven.
