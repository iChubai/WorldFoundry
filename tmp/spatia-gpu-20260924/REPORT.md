# Spatia GPU validation

The public `SpatiaPipeline` loaded the local `Jinjing713/Spatia` control and LoRA weights, `Wan-AI/Wan2.2-TI2V-5B`, and `facebook/map-anything` through the in-tree runtime on physical GPU 3. Its input was the local Wan example cat photograph, a synthetic 17-pose dense W2C camera trajectory, pixel-space camera intrinsics, and a matching text prompt. The run used 40 denoising steps and produced [demo-quality.mp4](demo-quality.mp4): 17/17 decodable frames at 832×480 and 16 FPS. [validation-quality.json](validation-quality.json) records a 69.19/255 pixel standard deviation and 43.93/255 first-to-last mean absolute difference. In the [contact sheet](contact-quality.jpg), the cat, water, and hills remain recognizable through the sequence, with visible viewpoint and content changes. The cat appears horizontally broad; visual fidelity and trajectory accuracy are not established by this one synthetic path.

The initial run failed during point-cloud rendering because the installed PyTorch3D extension was built for a different torch ABI (`undefined symbol: _ZN3c104cuda9SetDeviceEi`). The in-tree renderer now uses a Torch depth-buffer point splat when PyTorch3D cannot load. The next smoke run exposed another issue: the public pipeline wrote pixel-space intrinsics to a file that Spatia's MapAnything and renderer interpret as normalized values, creating nearly black control frames. The pipeline now divides focal lengths and principal points by output width and height when writing that file. The subprocess wrapper also retains stderr on failure. [demo-fixed.mp4](demo-fixed.mp4) and [validation-fixed.json](validation-fixed.json) are the successful 9-frame, 4-step smoke evidence after both repairs; [demo-quality-result.json](demo-quality-result.json) records the full run.

This validates local checkpoint-backed inference, camera input plumbing, non-black point-cloud control rendering, video decoding, and export. The Torch renderer is a fallback with nearest-depth splats rather than PyTorch3D's alpha compositor, so it does not establish pixel parity with the official renderer. One image and a synthetic camera path do not establish camera-control accuracy, source-video consistency, or benchmark quality.
