# UniAnimate-DiT short single-GPU validation

The WorldFoundry `OfficialVideoRuntime` route loaded the local Wan2.1-I2V-14B-720P base and `ZheWang123/UniAnimate-DiT` LoRA in the unified CUDA environment on physical GPU 3. It generated [demo.mp4](demo.mp4): 9/9 decodable frames at 288×480 and 15 FPS, using four denoising steps. [result.json](result.json) records the exact command and artifact SHA-256; [validation.json](validation.json) records full-frame decode and simple pixel checks. [contact.jpg](contact.jpg) shows frames 0, 4, and 8. The person and kitchen stay coherent, with slight arm and body change across the short sequence.

The reference is a cropped real dance photo from local FastVideo assets. The nine pose images are schematic synthetic conditioning prepared in [data](data), so this run verifies checkpoint loading, user prompt and image routing, pose conditioning, and video export. It does **not** establish official 81-frame/50-step quality, accurate motion following, or benchmark scores. The source paths and short-run parameters are captured in [preflight.json](preflight.json).

The run exposed two integration defects, now fixed in `worldfoundry_runner.py` and the runtime config: the supplied prompt and reference image had been ignored in favor of hard-coded demo values, and a directory containing only `pose.jpg` was incorrectly accepted as a complete pose sequence. The generated script was parsed and checked for the requested prompt, image, dimensions, frame count, and step count before the GPU run. `git diff --check` passed for the edited runtime files.
