# WoW-1-Wan-1.3B-2M GPU validation

The local public `X-Humanoid/WoW-1-Wan-1.3B-2M` checkpoint loaded through WorldFoundry's `WoWPipeline` on H100 GPU 1 and completed image-conditioned video generation. The final run used one real toy photo, a robot-arm prompt, seed 42, the model's 50 denoising steps, nine frames, tiled VAE, and 15 fps output. [result.json](result.json) records nine decoded 832×480 RGB frames with nonconstant finite pixels and 15.56 GB peak PyTorch allocation; [future_world.mp4](future_world.mp4) has SHA-256 `b94f7ecef5c7f43a71617016bc6cf71a7ea637adc379a0f0b827300002d46bd0`.

I inspected frames 0, 4, and 8 in [contact-0-4-8.jpg](contact-0-4-8.jpg). Frame 0 has the input turquoise toy on a plate on the red table. By frame 4, the scene has become a black gloved arm holding a turquoise object against a smooth backdrop; the table and wall have vanished. Frame 8 remains in that new scene. An earlier 20-step run ([contact](contact-0-4-8-20step.jpg), [result](result-20step.json)) showed the same abrupt replacement. This is a **quality concern** for this out-of-domain prompt/photo pair, not evidence of an implementation crash or an action-control score. [quality-review.json](quality-review.json) records frame metrics and the visual finding.

The first 20-step run used the optional `enable_vram_management=False` path and failed while encoding text because the loader left the text encoder on CPU while passing CUDA token IDs. [WoWSynthesis](../../worldfoundry/synthesis/visual_generation/wow/wow_synthesis.py) now moves the native pipeline to the requested device when VRAM management is disabled. The 50-step run used that repaired path and completed; the default managed path also completed a separate 20-step run. The exact replay script is [run.py](run.py), with [50-step log](full50-no-vram.log) and [managed-path log](retry-default-vram.log). No inverse-dynamics or SOPHIA branch was exercised.
