# WoW-1-Wan-1.3B-2M prompt-sensitivity recheck

The previous checkpoint-backed WoW run abruptly replaced the toy, plate, red table, and wall with a black-gloved-arm scene under a robot-arm prompt. I repeated the GPU 1 run using the same public checkpoint, input photograph, seed 42, 50 steps, nine frames, tiled VAE, and disabled VRAM management. Only the prompt changed to ask that the toy and room stay in view while the camera moves slightly closer. [run.py](run.py), [run.log](run.log), [result.json](result.json), and [status.json](status.json) preserve the replay and result. The output is [future_world.mp4](future_world.mp4), SHA-256 `dbd438ea6e9da68e91315abde1dd8618a5577dff07179b3de458deca1cca87f4`, with nine decodable 832×480 frames.

I viewed frames 0, 4, and 8 in [contact-0-4-8.jpg](contact-0-4-8.jpg). The turquoise toy, plate, red table, and wall remain in all three; the later frames look somewhat softer and fainter, but the abrupt scene replacement does not occur. Mean absolute pixel difference from frame 0 is 6.87 at frame 4 and 11.16 at frame 8, versus 43.44 and 45.19 in the [robot-arm prompt run](../wow-13b-gpu-20260923/REPORT.md). This paired check shows that the original quality concern is prompt-sensitive for this photograph. It does not prove an implementation bug or calibrated camera motion, and the robot-arm run remains marked **quality concern**. [quality-review.json](quality-review.json) records the comparison.
