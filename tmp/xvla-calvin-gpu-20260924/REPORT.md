# X-VLA Calvin ABC→D GPU validation

The local `2toINF/X-VLA-Calvin-ABC_D` checkpoint is a readable 3.52 GB safetensors file with 903 tensors. WorldFoundry's in-tree X-VLA pipeline loaded it on H100 GPU 1 and produced a finite 30×20 action chunk with CALVIN domain ID 2, seed 42, and ten denoising steps. [validation.json](validation.json) records the output range −0.424 to 1.000, standard deviation 0.317, and nondegenerate first-arm rotation features; [status.json](status.json), [actions.json](actions.json), [result.json](result.json), and [run.log](run.log) preserve the full run. Peak PyTorch GPU allocation was 3.68 GB. No project code change was needed.

The input was the first frame of episode 0 from the pinned third-party [CALVIN debug mirror](../calvin-fixture-20260922/fixture.json): its actual base and wrist images, task text, and 7D state. [case.json](case.json) records an exploratory conversion from xyz and Euler angles to a 20D X-VLA EE6D state with raw gripper width and zero padding. This is **verified inference only**. The fixture is not the official D test split, the state adapter has not been confirmed against the official X-VLA CALVIN client, and there was no closed-loop rollout or task score. [quality-review.json](quality-review.json) records these limits.

The [checkpoint preflight](checkpoint-preflight.json) found that DolphinFS reports low allocated-block counts for several other X-VLA files even when safetensors tensors can be read. Those counts alone cannot establish missing weights; a loader or tensor-read check is required before marking a variant blocked.
