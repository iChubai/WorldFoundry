# X-WAM RoboTwin-SFT future-world GPU validation

The public RoboTwin-SFT DeepSpeed checkpoint loaded with strict state assignment on GPU 2, and the WorldFoundry `generate_world=True` route ran the configured 50 video denoising steps with 10 action steps. The input was one real toy photograph repeated as three camera views, a synthetic zero 16D robot state, the instruction to move the gripper toward the object, and seed 42. This is a runtime check, not a real RoboTwin rollout.

The run generated [future_world.mp4](future_world.mp4), a decodable 9-frame, 256×960 H.264 RGB mosaic of three 320-pixel-wide views at the configured 5 fps. Its SHA-256 is `6d968d404fd4628aadd248d171c0cbbfcacd6d2ed1c5213ea85c9c12cb728e29`. The 32×14 action chunk and 9×16 proprioception prediction in [result.json](result.json) are finite. [status.json](status.json) records decoding and pixel-range checks; [quality-review.json](quality-review.json) records temporal differences and sharpness by view. The total script runtime, including loading the 37 GB checkpoint, was 94.89 seconds.

I reviewed [contact.jpg](contact.jpg), whose rows are frames 0, 4, and 8. All three panels initially retain the toy, plate, red table, and wall. By frame 8, the middle view crops/warps the red table and loses the toy, while the right view shows a distorted toy. The first view remains more coherent. This is a **quality concern** under the repeated-photo synthetic three-camera condition. It does not establish a model implementation bug, multi-camera accuracy, instruction following, action accuracy, or task success. The optional depth branch was not run.

Reproduction: `CUDA_VISIBLE_DEVICES=2 OMP_NUM_THREADS=8 OPENBLAS_NUM_THREADS=8 NUMEXPR_NUM_THREADS=8 MKL_NUM_THREADS=8 ../envs/worldfoundry-unified-cu121/bin/python -u tmp/xwam-world-gpu-20260923/run.py`. No project code change was needed for this branch beyond the already present restricted DeepSpeed `set` allowlist used by the action-only validation.
